## 先说问题（不列优点）

1. **职责边界没写进界面**：插件是纯读方（`main.rb:21-22`），却在左栏放了一个长得像主行动按钮的「+ 在 ID BOX 里导入」（`panel.html:634-636`），它没有任何 handler。导入的真正职责链在主程序（`App.tsx:1471-1472` → `store.ts:3631/3653` → `preload/index.ts:82-83` → `main/index.ts:1165` → `main/importer.ts:369`）。一个点不动的假按钮，比没有按钮更糟。
2. **一个不可点的元素被做成了设置入口的样子**：齿轮 SVG（`panel.html:527-530`）+ 展示行（`:639-642`）没有任何绑定，也没有 `cursor: pointer`（`:372`）。全文件「设置」二字 0 命中【查证】。用户说「设置是按不了的」，判断准确 —— 它本来就不是按钮。
3. **同一份筛选状态有 6 个写入源、四种重绘范围**：`state.activeCategory1` 6 处赋值、`activeKind` 4 处、`sortKey` 3 处【查证：`panel.html:1745-1746/1758/1772-1774/1779/1781/1786/1788/1825-1827`】；四段 handler 逐字重复 `renderSide/renderChips/renderList/renderCount`（`:1747-1750`、`:1759-1762`、`:1790-1793`、`:1828-1831`）；而 `applyQuery` 只跑 2 件（`:1555-1556`）、`.seg` 只跑 1 件（`:1811`）、`applyDensity` 跑 0 件（`:1619-1632`）。**没有任何一处决定「该重绘多少」**，这是「逻辑上的问题非常大」的具体所指。
4. **分类触发与主软件不是同一套语义**：主软件是「三层筛选 + 逐级展开树」（`Sidebar.tsx:424-427/452-458/928-1133`）；插件是「左栏两层 + 中栏 4 个 chip 点击循环切换」（`panel.html:1796-1799`）。chip 带着 `▾` 下拉箭头却是循环切换（`:1441/1448/1455`），属于**假控件**；而主软件中栏根本没有分类 chip（`App.tsx:1486-1700`）。二级分类数据完整且已实测充足（§3.5），插件只缺 UI 与 `activeCategory2` 状态（`panel.html:687-704` 无此字段）——**插件的一级触发已与本体同构，唯一缺口就是 `activeCategory2` 这一维度**（`panel.html:1313-1331/1737-1763` 注释自述）。
5. **深色是系统跟随、插件里无法控制**：唯一来源是 `panel.html:138-199` 与 `:431-435` 的 `@media (prefers-color-scheme: dark)`，Ruby 侧 `theme|dark|data-theme|set_theme|prefers-color` 0 命中、payload 22 个键无主题字段【查证】。用户在 SketchUp 里既关不掉也调不了，效果差却无从下手。
6. **两处报告未覆盖的既存缺陷**（本文复核新发现，详见 §10）：未分类哨兵与 `matches()` 特判冲突 → 「未分类」节点可能计数 N、点进去 0 条；分类筛选导致 0 条时空态文案显示「没有匹配「」的记录。」。二者都会在本次新增二级筛选维度后被放大。**其中 51 条哨兵记录还直接决定渐进披露的正确性**：它们绝不能被当成真实二级值渲染（§3.5 / §3.7）。

**它本来就不是按钮。**【查证】

### 3.7 ⚠️ 复核新发现：未分类哨兵会让节点「计数 N、点进去 0 条」

| 步骤 | 代码 | 结果 |
| --- | --- | --- |
| 写侧 | `pluginSnapshot.ts:258-259`：`nullableString(asset.categoryX) ?? UNCLASSIFIED`；`src/shared/taxonomy.ts:19` `UNCLASSIFIED = '未分类'` | 空的 `category1/category2` 被写成字符串哨兵 `'未分类'`，不是 `null` |
| 读侧 | `lib/loader.rb:352-353` 用 `Support.nil_text`；`lib/core.rb:169-172` 只把**空串**转 `nil`，非空串原样返回 | 哨兵原样透传到 payload |
| 真实索引 | 本文独立读取：首条记录即 `"category2":"未分类"`；`"category2":null` **0 条**【查证】。主理人实测：全量字面「未分类」**51 条**（33 条属 hdri）、插件可见范围内 **18 条** | 哨兵确实存在，且数量不可忽略 |
| 聚合 | `topCategories` `:1351-1352` `name = first \|\| UNCLASSIFIED_LABEL` | `'未分类'` 非空 ⇒ 直接作为名字，与真·空值归来的「未分类」**同名合并**，计数显示 N |
| 筛选 | `matches()` `:1179-1181` 特判 `if (state.activeCategory1 === UNCLASSIFIED_LABEL) { if (category1) return false; }` | 用户点「未分类」⇒ 要求 `category1` 为**空**；但记录里是 `'未分类'`（非空）⇒ **全部返回 false** |

⇒ **「未分类」节点显示有 N 条，点进去却一条不显示**【查证】。两份报告未覆盖此项。

**推荐修法**（随 T03 一并施工，不单独立卡）：判定统一为「空值 **或** 哨兵值都算未分类」：

```js
function isUnclassified(value) {
  var v = textOf(value).trim();
  return v === '' || v === UNCLASSIFIED_LABEL;
}
```

`isUnclassified()` 在本轮有**两处用途，缺一不可**：

1. **一级层**：`matches()` 的特判改为「`state.activeCategory1 === UNCLASSIFIED_LABEL` 时只放行 `isUnclassified(record.category1)`」，`topCategories` 的归名也用它 ⇒ 修好「计数 N、点进去 0 条」。
2. **二级层**：`secondCategories()` 用它**剔除哨兵记录**（`if (isUnclassified(record.category2)) continue;`），使「未分类」**不生成二级节点**；这是 D05 渐进披露「只为真实值展开」的判据基础。面板不得出现名为「未分类」的二级节点（T03 硬断言）。

**不改动写侧 `pluginSnapshot.ts`、不改 payload schema**（A8 只增不删、§9 明确不做），只在插件读侧兼容。

### 4.2 单一调度函数设计

```js
/**
 * 唯一的状态写入 + 重绘调度入口（IIFE 内闭包函数，不挂 window、不新增全局变量）。
 * 任何 handler / Ruby 注入 / 定时器都不得直接写 state 的筛选字段，
 * 也不得直接调用 renderSide/renderChips/renderList/renderCount。
 *
 * @param {Object} patch  白名单字段的子集：
 *        { activeKind, activeCategory1, activeCategory2, expandedL1,
 *          sortKey, query, viewMode, density, data, selectedId }
 *        未在 patch 中出现的字段保持原值。'data' 例外：整份 payload 覆盖。
 * @param {String} reason 枚举：
 *        'data' | 'filter' | 'query' | 'sort' | 'view' | 'density' | 'freshness' | 'reset'
 * @returns {undefined}
 */
function commit(patch, reason) {
  // 1) 白名单合并：唯一写入点；未知字段静默忽略（防止把临时变量写进 state）
  // 2) 联动不变量（集中在这里，不再散落 6 处）：
  //    · 改 activeKind        ⇒ 清 activeCategory1 / activeCategory2 / expandedL1
  //    · 改 activeCategory1   ⇒ 清 activeCategory2 / expandedL1
  //    · 改 activeCategory2   ⇒ 保持 activeCategory1（对齐 Sidebar.tsx:1106-1118）
  //    · 'reset'              ⇒ 四者 + sortKey 复位（对齐 allViewFilterPatch 的清维度语义）
  //    · query 变化           ⇒ dismissUndoPill()
  //    · 'data'               ⇒ dismissUndoPill() + 更新派生字段（kindLabels 等）
  // 3) 按 reason 查 REPAINT_MATRIX 决定重绘集合，逐个调用
  // 4) 收尾统一 renderCount()（除非矩阵标为 skip）
}
```
