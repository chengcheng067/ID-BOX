### 6.3 ★ 详情页能不能一次 HTTP 拿到完整三级路径 —— **能，而且是现成的**

这是本次最有价值的发现。CAD 详情页的 `<script id="__NEXT_DATA__">` 里有一组 **`breadcrumb_data`**，直接给出**完整分类路径，每级都带 `termId` + `cname`**：

```json
"breadcrumb_data": [
  {"termId": 18074, "showName": "平立面系统图", "cname": "plxtt",        "href": "f18074"},
  {"termId": 17136, "showName": "平面图",       "cname": "pingmiantu",  "href": "f18074s17136"},
  {"termId": 16241, "showName": "工装平面图",   "cname": "gongzhuangpmt","href": "f18074s16241"}
]
```

界面实测（`document.body.innerText`，未登录）：`AutoCAD2007 | 软件版本 | DWG | 图纸格式 | 工装平面图 | 分类 | -- | 图纸类型`
→ **界面只给「末级名称」，不给路径**；完整路径只存在于 HTML 的 `breadcrumb_data` 里。

配套字段：

- `res.classifyBaseName` = 末级名称（单字符串，**不含路径**，且实测会和末级对不上，见 §七）。
- `res.propertyValue` 里有 `{"name":"设计风格","propertyValue":"现代简约"}` —— **注意它的取值不在风格筛选排的 20 项词表里**（「现代简约」≠「现代」+「简约」），不能直接当风格枚举用。
- `pageProps.res.classifyId`（如 116638 / 114241）是**另一套 id 空间**，与 `termId` 不通。

**实测覆盖（36 个随机 CAD 详情页，零 cookie、默认 UA、纯 HTTP GET）**

| 结果 | 数量 |
| ---- | -- |
| 拿到 3 级路径 | **25** |
| 拿到 2 级路径 | 10 |
| 路径为空 | 1 |
| 其中路径里有「当前筛选树里不存在的词」 | **8**（L1 不存在 5 个、L2 不存在 4 个、L3 不存在 1 个，有重叠） |

→ **判读：这条路通，但面包屑用的是「历史词表」，不是当前筛选树。** 出现的旧词包括一级 `室内空间`(14585)、`节点图块`(13773)，二级 `文化教育建筑`(14627)、`庭院`(14587)、`家装图库`(17138)、`其他图库`(14617)。其中 `室内空间` 下面还挂着 `家装空间`（即现在的第 3 个一级曾是其子级）。

**给接线的结论**：详情页一次 GET 就能拿路径，**不需要抄词表也能知道归属**；但要落成我们自己的枚举，必须再配一张「历史词 → 当前词」的别名表（约 8/36 ≈ 22% 的样本会命中这张表）。

### 6.4 列表页也有路径字段

一级/二级/三级页面的 `initListParam.filters.web_cate` 直接给当前路径字符串，用 `$##$` 分隔：

```json
"filters": {"type": "cad", "web_cate": "工装空间$##$餐饮空间$##$", "sort_type": 0}
```

`rules` 里同时有 `entry`（当前 cname）与 `page`（页码）。反爬方面：零 cookie、默认 UA、纯 GET 即可，未遇验证码/限流；**但详情页的浏览器界面有软登录墙**（见 §七-11）。

### 8.7 顺带发现：站方自己的「分类树」与「列表页」不一致（比补词更重要）

`博物馆` 这个词在**站方分类树**里挂的是 `工装空间 > 文化空间 > 博物馆`（`bowuguansn.html`）；
而 `建筑设计 > 文化建筑` 下另有 `博物馆建筑`（`bowuguan.html`）。
但**站方自己的二级列表页**把标题带「博物馆」的资产全部归到了 `建筑设计/文化建筑`。

真值样本里含「博物馆」的 11 条，实测（v0.8.6，1091 条基准）：

| 结果 | 条数 | 说明 |
|---|---|---|
| ✅ 判对 | **2** | 都以「博物馆建筑」结尾 → 命中站方三级 `建筑设计/文化建筑/博物馆建筑` |
| ❌ 判进 `工装空间/文化空间` | **4** | 都以「博物馆」结尾 → 命中站方三级 `工装空间/文化空间/博物馆`，**而真值要的是 文化建筑** |
| ❌ 其它错/未分类 | 5 | 以「平面图」「规划设计」「详图」结尾，或被图种词抢走 |

那 4 条被站方树"带偏"的标题：
```
300㎡科技创新集团展厅CAD施工图 陈列厅 博物馆 施工图      → 工装空间/文化空间（真值 建筑设计/文化建筑）
现代博物馆 历史 非遗 文化 博物馆 展厅 施工图            → 工装空间/文化空间（同上）
庐江县博物馆 档案馆 设计方案 文本 施工图 概念方案 效果图  → 工装空间/文化空间（同上）
展厅展览企业文化科技展示展馆博物馆                      → 工装空间/文化空间（同上）
```

**为什么这条值得记**：
1. 它解释了「照抄词表为什么追不上真值」——**连站方自己都不一致**：树里 `博物馆` 属于工装空间，列表页却按 `文化建筑` 筛。任何照抄单一来源的做法，都会在这类词上系统性错。
2. 它是"准确率只有 42.5%"的一半原因（另一半是图种词尾：45.6% 标题以「施工图」结尾）。
3. **处理方式：不修**。给 alias 表加"一个 term 指向两个二级"的能力，等于把站方的不确定性藏进代码 ——
   宁可让这 4 条按站方树落 `工装空间/文化空间`（可解释、可追溯），也不引入"同名看上下文"的黑箱。
   将来站方自己统一了，我们重跑探针即可。
