## 新增 · CAD 图纸成为独立资产大类

以前 `.dwg` / `.dxf` 被当成普通模型收进去，和 `.skp` 混在一起，既筛不出也认不出。现在 CAD 是**独立一类**：

- 侧栏多出「CAD图纸」节点，紧跟「模型」之后 —— 点它只筛图纸，模型计数不再混进图纸
- 落入 `<库>/CAD/<一级>/<二级>/<资产名>`，四层深度和其他大类一致
- 文件视图里 `.dwg` 卡片是**框内「CAD」三个红字**（AutoCAD 红），和 SU / max 的封面语言统一
- 同时含 `.skp` 和 `.dwg` 的包仍判为「模型」（模型是主内容，图纸是附件），只有纯图纸的包才落 CAD

**CAD 封面两条来源**（按优先级）：

1. **DWG 内嵌缩略图** —— 直接从图纸文件里提取，本地立刻可用，不需要联网
2. **知末 sgt 频道的图** —— 文件名带 `ID_<数字>` 时反查施工图频道
3. 都没有 → 红色「CAD」占位

## 新增 · CAD 分类词表接入

词表仍然只从站方**原始抄录**，不自创词条：

- 一级 **10 项** / 二级 **102 项** / 三级 **368 项**
- 三层作用域隔离：CAD 分类器**只在 CAD 词表里匹配，不再回落通用词表**（避免「家具」这类通用词把图纸吸走误判）
- 手动改派也补齐了两级级联 —— 以前 CAD 资产的分类选择器一级是空数组，选不了
- 实测二级命中率 **33.6% → 42.5%**（补 13 个派生归并词后的真实标注集结果）

## 新增 · 分类三源交叉验证

以前分类只信「标题关键词」一个来源，标题写得含糊就必然分错。现在**三个来源交叉比对**：

| 来源 | 是什么 |
|---|---|
| S1 标题语义 | 现有分类器按标题关键词匹配的结果 |
| S2 站方面包屑 | 知末详情页里站方自己的分类路径 |
| S3 站方三级名 | 站方分类树最深节点的名字（仅作旁证） |

五档判定，**对不上就绝不硬猜**：

- **high** —— 两个来源一致，直接定案
- **medium-s2** —— 只有站方来源，采用并搬目录
- **medium-s1** —— 只有标题语义，采用但不搬
- **conflict** —— **两个来源一级分类不同 → 一律不定案，进「待确认」**
- **none** —— 两边都空

真实数据实测（157 条 conflict 逐条核过）：其中 **44.6% 是标题语义被「图种三册」误吸**，站方真值只有 21 条在那三册里 —— 这就是不能自动定案、必须交给用户裁定的硬证据。

## 新增 · 「待确认」队列

交叉验证判不了的那批不再静默落到未分类，而是进一个**专门的待办入口**：

- 侧栏「待确认」行（**0 条时整行不渲染**，不占位置）
- 整理浮层里逐条显示**三个来源的原始判断**：我们的分类 / 站方路径 / 站方三级名，方便你一眼看出分歧在哪
- 你确认后写库并打上定案时间戳，之后不再进任何队列
- 和原有「未分类」队列**共用同一个整理浮层**，只是按原因切换队列，交互不用重学

## 新增 · 未分类整理流水线

以前未分类资产只能一个个点开右栏改派。现在有连续整理的路径：**一屏一张 + 一键归类 + 自动跳下一张**。

## 新增 · 整理浮层的滑动手势（探探式）

整理时「确认」/「跳过」不再只是两个按钮，卡片本身会飞：

- **跳过 → 卡片向左飞出去**
- **确认 → 卡片向右飞出去**
- 飞完之后下一张从反方向滑进来，形成连续的手感

实现上只用了一套 keyframes，方向由 CSS 变量 `--triage-dir` 取 `1` / `-1` 驱动，两个方向共享同一条曲线，不会出现左右手感不一致。

**动效性能**跟设置里的「动效性能」三档联动（流畅 250ms / 均衡 320ms / 极致 340ms）。系统开启「减少动态效果」时降级为 **160ms 纯透明度淡出**，不做位移动画。

**连点保护**：快速连点两次跳过不会跳过两张 —— 第一次点击就同步上锁，动画结束才解锁（不是用 `setTimeout` 猜时长）。

## 新增 · HDR 分类：接口已预留，词表留给以后

这是本版一个**只做了管道、没做内容**的部分，写清楚以免误解：

**现在的事实**：HDR / EXR 资产导入后**一律落在 `HDRI/未分类/未分类`**，因为它们**没有任何分类词表**。这不是 bug，是刻意的 —— 知末的 HDR 频道没有可抄录的一级/二级结构，我们不会为了填满界面而自创词条。

**已经打通的部分**（手动改派整条链对 HDR 是通的）：

- 右栏详情面板的「分类」区块对 HDR 正常显示，点一级/二级都能改
- HDR 没有预设词表 → 选择器一级是**自由输入**，二级同样是自由输入
- 你手输的一级 / 二级会自动进**自定义词表**，下次直接可选，并带「自定义」角标
- 落盘、目录搬迁、缩略图重生、左栏分类计数刷新，这一整条链对 HDR 与你手动改派模型时**完全一致**
- 自动分类的一级闸门对 HDR 恒为「拒绝」—— 所以**永远不会有一个 HDR 被自动塞进别的类目**，只会停在未分类等人来定

**以后补词表要动哪里**（留给未来，本版不做）：加一册 HDR 一级/二级词表需要改 `CHANNEL_LEVEL1` 的类型键、加一份 `HDRI_LEVEL1_LIST`、并在 `level1OptionsFor` 里加一条分支 —— 也就是说**接口形状已经定好了，缺的是数据和三处接线**，不是重新设计。

## 新增 · 材质球形态可选（球 / 平面 / 圆角盒）

自定义渲染弹窗里多了一个形态分段控件，三个选项：

- **球** —— 默认，看整体质感
- **平面** —— 正方形，看贴图本身的平铺与接缝
- **圆角盒** —— 看棱角处的拉伸与法线表现

形态参与球图缓存命名（同一材质换了形态，成像必然不同），所以切形态会重渲一次，之后走缓存。

## 新增 · webp / tiff 尺寸识别

分辨率筛选以前只认 png / jpg / hdr / exr 的尺寸，webp 和 tiff 一律「未知」→ 永远进不了任何分辨率档。现在补齐了探测链 **PNG → JPEG → WEBP → TIFF**。

## 新增 · 「全部」视图专注模式

体积 / 分辨率 / 格式三个筛选入口在「全部」视图**不再显示** —— 那里是总览，不需要这层细筛，进到具体大类再调整。

因为这三项在「全部」下没有入口，又不能让它们**隐形生效**（筛着东西却看不见、也点不掉），所以顺带加了一层兜底：真的存在隐形筛选时，中栏头会显示一条「全部视图已隐去 N 个筛选」，点一下就能清掉。

## 修复 · 筛选值隐形生效且取消不掉（共五条同类死角）

这是本版修得最深的一类问题，起因是你实测报的：

> 在模型里选了格式，没取消就切到「全部」，看不到 SU 模型了。

根因不在某一个字段，而是**同一份判定被手写了三遍**，每加一个筛选维度就得记住改三个地方：

1. 侧栏「全部」按钮的**清理列表**漏 2 个字段
2. 侧栏「全部」按钮的**高亮判定**漏同样 2 个字段 —— 隐形筛选时左栏仍显示「全部」选中，等于界面在骗人
3. 「重复资产」按钮的清理列表漏 **6** 个字段
4. 标签组只显示前 12 个 → 筛中的标签跌出列表后入口消失
5. **智能集合**：在「全部」视图存下的筛选快照本身就带着矛盾状态，套用后同样隐形过滤

修法是把三处手写清单收敛成**唯一定义**，并且「全部」视图下的判定改为复用已有的维度枚举 —— 将来再加维度只需改一处，不会再漏。

同时明确了一点：**「模型 → 全部 → 模型」来回切，格式选择不能丢**。所以清理只发生在「落盘 / 读盘」这两个持久化边界，中间切视图时保留。

## 修复 · 整理队列串类（HDR 点整理弹出材质）

你实测报的：

> HDR 的这个「未分类」，点了整理以后，弹出来的是材质的整理，不是 HDR 的整理。

根因是三套「未分类」口径错配：侧栏那个数字按**当前展开的大类**算，而整理队列取的是**全库**。所以从 HDR 那一行点进去，队列里装的是整个库。

现在整理队列**按当前大类收窄** —— 在哪一类里点整理，就只整理那一类。侧栏数字与浮层条数从此同口径，能对上。

「待确认」队列**刻意不跟大类走**：侧栏「待确认 N」本身就是全库口径（它统计的是整个库里所有有分歧的资产），跟着收窄反而会让数字与浮层再次对不上。

## 修复 · 导入后杂质文件没有被删除

知末的压缩包里常年夹着三件套：扫码推广图、`知末CAD图纸-….html`、`知末网说明.txt`。以前只做到「不进文件索引」，**磁盘上照样留着**，你在资源管理器里仍然看得见。

现在落盘后直接物理删除，批次结束会弹一条「已清理 N 个推广/说明文件（导入时自动删除，不进回收站）」。

判定刻意做得**很窄**，只删两类：

- 扩展名本身不是素材的（`.html` `.htm` `.txt` `.url` `.lnk`）
- 文件名带站方推广专属短语的（微信扫码 / 扫码关注 / 二维码 / qrcode / 知末网说明 …）

为什么不能直接用现有的宽松规则：实测它会把 **`设计说明.dwg`、`施工说明.dwg`、`图例说明.dwg`、`下载的模型.skp` 全部判成垃圾** —— 「说明」是标准 CAD 图纸专业名，「下载」也是常见模型名。删除不可逆、不进回收站，判错就是丢图纸。`.json` 也特意排除（PBR 材质包的元数据，删了会丢材质名和标签）。

## 改进 · 全局焦点环统一成品牌蓝（修掉橙色边框）

你报的：

> 很多时候在咱们的软件里面，按下按钮时，任何位置都会出现一个橙色边框。

根因很具体：全仓**只有一个按钮**定义过 focus 样式，其余全部没定义 → 退回 Chromium 的默认 `:focus-visible` 轮廓，而 Chromium 在 Windows 上取的是**系统强调色**。你的系统强调色是橙金色，于是点哪都冒橙框 —— 那个颜色既不在设计 token 里，也违反「全局不用橙色高亮」的规矩。

现在全局统一：

- 键盘 **Tab** 过来 → 显示品牌蓝焦点环（`2px solid var(--accent)`，外扩 2px）
- **鼠标点击** → 不出环（`button:focus:not(:focus-visible)`）
- 输入框 / 文本域 / 下拉 → 不出轮廓（它们自己有边框高亮语言）

实测 773 个可聚焦元素，**橙色轮廓 0 处**。

## 改进 · 侧栏「整理」按钮不再压住数字

以前那个按钮是绝对定位浮在「未分类 N」这一行上的，数字末尾被盖掉。现在改成**同一行的并列元素**：名字可截断、数字固定宽度、按钮固定宽度，三个互不挤压。按钮也换成了品牌蓝实底小按钮，比原来的灰字更像个能点的东西。

## 改进 · 整理浮层改成实心页面感

以前浮层是半透明的，底下的卡片网格透出来，视觉上是「悬在半空的一块毛玻璃」，接不住面板。现在外层是**实心卡片** + 统一的弹窗阴影，和材质球渲染弹窗、设置页是同一套承载方式。

同时把溢出的职责下移：外层允许子元素飞出（滑动手势需要），裁切由左侧图框和右侧滚动列各自负责 —— 所以飞出去的卡片不会被边框切断。

## 改进 · 中栏提示文案按大类分场合

以前不管在哪个大类，中栏头都提示「HDR 是直接进预览」。现在按大类说该说的话：

- **HDR** → 「双击卡片直接预览 · 拖拽卡片可拖到建模软件」
- **其余大类** → 「双击卡片查看文件 · 拖拽卡片可拖到建模软件」

## 删除 · 「词表待补」标签

上一版侧栏有个「词表待补」标签，本意是提示「这些资产的分类词表还没补全」。实际效果是**没有给出任何可操作的入口** —— 用户看到它，不知道该去哪补、也不知道怎么让它消失。

这类「只提出问题、不给动作」的标签不如不给。已整个移除。

## 改进 · 3ds Max 卡片

- 徽标文案 `3D Max` → **`max`**（三个字母，和 `SU` / `CAD` 同视觉语言）
- 颜色从旧青色换成 AutoCAD 一族的青蓝，深浅主题各一套

顺带修掉一个老缺陷：`max` 卡片以前挂的两个 Tailwind 类**都不存在**，导致它一直没有底色、字色靠继承 —— 这解释了它一直比 `.skp` 卡片暗一块。

## 修复 · 压缩包解压兜底链从未触发

GBK 乱码嗅探漏了一整段 PUA 码位（`0xE000–0xF8FF`，GBK 解码失败时最常见落点），加上 `-mcp=GBK` 本身就是 7-Zip 的非法参数 —— 整条兜底链实际上是死的。现在能真正接住乱码包名。

## 已知限制

- 仅支持 Windows
- 知末抓取依赖站方页面结构，站方改版可能失效（失败会明确报原因，不影响其它封面来源）
- 封装里带 HTML / TXT 的**真素材**会被删 —— 这是我们刻意选的边界：素材包里纯文本与网页没有资产意义
- **历史库存量杂质不会自动清理**，只有重新导入才会删
- `.dxf` 目前没有本地封面来源（只有 `.dwg` 能提取内嵌预览）
- **HDR 没有预设分类词表**，导入后一律停「未分类」，只能手动改派（接口已通，词表待补）
