### 4.2 诉求本质（【推断】，PM 读法，供纠正）

用户原话表面是「快速进入习惯项目的入口」，深层是三件事：
1. **减少导航步数**：现在进一个常用目录要「首页 → 分类 → 找到资产」，用户想要「一点直达」。
2. **复用外部既有结构**：「标准文件夹」与「允许用户自己导入标准文件夹」说明用户手上**已有一套目录组织习惯**，希望 ID BOX 认它、不要推倒重来。
3. **个性化工作台**：「在首页放置最近工作项目的文件夹快捷方式」是要一个**可自定义的常用入口区**，而非固定分类导航。

⚠️ **与现有架构的核心张力**：库目录是**固定四层**（`rescan.ts:129`），「项目」若作为第五层或外部目录，会撞上 `onIgnored(rel, 'depth')`（`rescan.ts:130`）被跳过。任何方案必须先回答「项目目录放在哪一层、是否进索引」，这是**第一约束**。

### 4.3 可选形态（≥3 个，含推荐）

| 形态 | 简述 | 代价 / 风险 | 与四层模型关系 |
| --- | --- | --- | --- |
| **A. 纯快捷方式（不改库结构）** | 首页增加「最近工作」区，存一组常用**资产目录**的快捷入口（点击直达该资产文件视图），本质是 `Asset.id` + 路径的收藏夹 | 最小；只新增一组偏好设置 + 首页 UI；**不动 rescan、不引入新实体**；快捷指向的资产被删/移动后需失效处理 | 完全不碰四层模型（`rescan.ts:129`） |
| **B. 「项目」作为自定义分组标签** | 复用「智能集合 / 自定义词表」思路，让用户把若干资产归进一个「项目」集合，首页给集合入口 | 中；需新实体 + 持久化 + 与既有筛选/智能集合共存；「标准文件夹导入」仍需定义格式 | 不改磁盘目录，只在索引侧加映射 |
| **C. 原生「项目」目录层（第五层 / 外部根）** | 允许用户指定「标准文件夹」root，ID BOX 按项目维度组织；首页放项目快捷入口 | **最大**：撞固定四层（`rescan.ts:129-130`）、`kind` 不由目录决定（`:133`）、需迁移策略；「导入标准文件夹」还要定义校验与冲突处置 | 直接冲突，须先改 rescan 契约，**风险最高** |
| **D（补充）. 最近使用排序** | 不加实体，只在首页/侧栏给「最近打开」列表（数据已有「累计使用次数 / 最常使用排序」字段口径，见 `types.ts:310-320` `useCount` 与 `recordAssetUse` 打点；**非时间型 lastUsed**） | 小；但只解决「快速到达」、不解决「标准文件夹导入」 | 不碰 |

**推荐（PM 读法，`【推断】`）**：**A（纯快捷方式）作为第一步**，理由：① 用户最迫切的是「一点直达」，A 已满足；② 零触碰 `rescan.ts:129` 固定四层这条最硬的约束；③ 「标准文件夹导入」可留在 B/C 单独拍板，避免一次改动面过大。若用户明确要「标准文件夹」是刚需，则选 C，但必须先由架构师评估四层模型改造代价（**不在本 PRD 裁定**）。
