## §0 TL;DR

主理人判断「首页这一屏全部使用率都不高」，要把它从「一个空白网格」改造成「有情绪价值的一屏」，拆成三块：

| 块 | 用户原话要点 | 参考源 | 性质 |
|---|---|---|---|
| **A 中间背景** | 「我们中间得有一个背景」 | tuneshape `particle-tide`（粒子潮汐） | 视觉底噪，不带功能 |
| **B 下方几栏** | 「我们有几个种类，就做几个文件夹」+「做个类似效果的方盒子这样有这样的打开动效」 | tuneshape `glass-folder`（玻璃文件夹） | **功能入口**，等价于现在的导航节点 |
| **C 侧栏数据** | 「新导入了几个模型，这个月我们整理了几个模型，分类删除了几个素材」 | 无（用户口述） | 数据指标，**须可延伸** |
| **D 排版** | 「只看排版不看实际内容」 | 小红书「灵感分享｜简约清爽 B 端界面设计_6_灯野鹿设计」 | 仅版式参考，不抄内容 |

一句话风险：**B 块本质是把左侧导航「搬」到首页做成文件夹卡片**，与 2026-11-06 U-1 拍板「不新增第 6 个导航节点」不是同一件事，但会引出一个新问题——首页文件夹卡片与左侧导航节点是否**双入口**。这是本轮**第一个要拍板的问题**（见 §5 Q-A）。

## §1 需求原文（逐字留档）

> 「我觉得现在咱们 idbox 本体软件的首页这一屏，全部使用率都不高，所以我们需要做一些有情绪价值的事情」
>
> 「只看排版不看实际内容，这是我找到的一个参考。比如我们中间得有一个背景，背景参考：`https://tuneshape.kai-nex.com/#/effect/particle-tide?from=%23%2Fcategory%2Fbackgrounds`」
>
> 「下方做几栏。比如我们有几个种类，就做几个文件夹，文件夹参考（当然我们可以做个类似效果的方盒子这样有这样的打开动效）：`https://tuneshape.kai-nex.com/#/effect/glass-folder?from=%23%2Fcategory%2Fcontainers`」
>
> 「侧栏就给一些我们最近整理的文件数据，比如说：新导入了几个模型，这个月我们整理了几个模型，分类删除了几个素材之类的。我觉得这个地方是需要有延伸的。」

拆解出的四个隐含判断（我的读法，供批注时纠正）：

1. **「首页这一屏」= 主程序启动后第一眼看到的那一屏**，不是某个二级页面。它现在的形态见 §2。
2. **「全部使用率都不高」** 是改造动机，不是需求本身 —— 意味着验收标准里应当包含「改造后这一屏有人用」，而不只是「变好看了」。
3. **「情绪价值」** 是用户自己的措辞，含义未定义。我在 §3 给了三种常见解释，需要主理人认领其中一种（否则后面所有设计判断没有依据）。
4. **「这个地方是需要有延伸的」** 明确指向 C 块 —— 指标区必须是**数据驱动的槽位**，不是写死的三行文案。

## §2 现状盘点（`home-inventory` 只读盘点，2026-11-07）

### §2.1 「首页这一屏」到底是哪一屏 —— 【查证】

**不存在独立的首页 / 欢迎页 / 概览组件。** 全仓无 Home / 概览 / 欢迎类组件，`package.json:20-31` 无路由库，`renderer/main.tsx:66-71` 只挂一个 `App`。

⇒ 「首页」= **侧栏「全部」节点的网格页**。判据：`libraryView==='assets' && filters.kind==='all' && !dupOnly && !folderViewAssetId`（`store.ts:1295-1316`、`App.tsx:812-817`、`App.tsx:1651`）。

⚠️ 易混点：`App.tsx:269` 的 `view` **只是 grid/list 排版态**，不是页面。

⇒ **对需求的直接影响**：「首页」与「全部素材网格」在物理上是同一屏。改造这一屏 = 改造主屏幕本身，**不是新增一个页面**。这会带来一个必须回答的问题（Q-F，见 §5）：改造后的背景/文件夹盒子，在用户点进「模型」节点后**还在不在**？如果还在，它就不是「首页专属」，而是常驻装饰。

### §2.3 种类常量（B 块做几个盒子的直接依据）—— 【查证】

`KIND_NAV_ORDER = ['model','cad','materialGroup','hdri','other']`（`classify.ts:184-192`）⇒ **5 个种类**。

`KIND_LABEL`（`classify.ts:40-47`）：模型 / 贴图 / HDRI / 材质预设 / CAD图纸 / 其他。注意 `KIND_FOLDER`（`:56-64`）里 **texture 与 material 共用「材质」目录**，但导航上属于 `materialGroup` 一个节点。

### §2.4 C 块数据可行性 —— 【查证 + 硬结论】

| 指标 | 能否算 | 依据 |
|---|---|---|
| 各类数量 / 总量 / 体积 | ✅ 现在就能 | `useVisibleAssets`（`store.ts:6111-6126`，注释记录 1 万条 2.6ms）；`Sidebar.tsx:198-208` 现成计数 |
| **本月新导入** | ✅ 能 | `Asset.importedAt`（`types.ts:414`） |
| 当前回收站条目数 | ✅ 能 | 回收站 = `assets` 里带 `deletedAt` 的行（`types.ts:356`），**保留原始 `importedAt`/`updatedAt`**（`store.ts:3372-3377`） |
| 待补分类数 | ✅ 能 | `classifyReview.decidedAt`（`types.ts:445`）+ `isCategoryIncomplete`（`App.tsx:97`） |
| **「这个月整理了几个」** | ❌ **算不出来** | 见下 |
| **「分类删除了几个素材」** | ❌ **算不出来** | 见下 |

**为什么算不出来（这是本轮最重要的一条结论）：**

1. **数据库只有 3 张表**：`assets` / `backups` / `aliases`（`db.ts:113-116`）。**没有任何操作日志表。**
2. `backups` 不是账本 —— 它是救急快照（`rescan-` / `rescan-pre-` / `reclass-` / `dup-clean-` 前缀），**只留约 3 条**（`store.ts:2212-2260`），不能按月聚合。
3. **硬删会物理删索引行**：`recycle` 档（`store.ts:3336`）、彻底删除/清空回收站（`store.ts:3501`、`store.ts:3532`）⇒ 删了就真没了，历史不可回算。
4. **`updatedAt` 不能冒充「整理」**：拖拽/批量指派只改 `updatedAt`（`store.ts:3631-3644`），收藏、评分、换封面全都会改它 ⇒ 用它算「整理了几个」会被污染成噪声。
5. `main/logger.ts:31` 的诊断日志**只留 7 天**，且是技术日志不是业务事件。

⇒ **C 块的后两条指标必须新开记账表、从零记账**。第一天用户看到的会是 **0**。这不是实现问题，是数据不存在。**Q-C 的核心就在这**：要么接受「从今天开始累计」，要么这两条指标换掉，要么接受「首启时给个『从今天开始记录』的说明」。

## §3 「情绪价值」的三种解释（须主理人认领一种）

| # | 解释 | 落地形态 | 代价 |
|---|---|---|---|
| **E1 呼吸感** | 屏幕上要有「活着的东西」——缓慢流动的背景、轻微的光影 | 中间背景动效 | 常驻 GPU/CPU 占用；低保真机型需降级开关 |
| **E2 藏品感** | 素材不是表格里的行，是「我收藏的东西」——有分类盒子、有封面、有打开动作 | 文件夹卡片 + 开盒动效 | 交互路径变长（要先进盒子才看到素材） |
| **E3 成就反馈** | 让我知道我攒了多少、整理了多少 | 侧栏数据指标 | 需要历史记账，现有数据可能算不出「这个月整理了几个」 |

用户原话同时要了 A/B/C 三块 ⇒ **大概率是 E1+E2+E3 全要**。但三块的成本差一个数量级（E1 是纯视觉、E3 要动数据层）。登记为 Q-B，让主理人排优先级或确认全要。

## §4 三块的需求边界（初稿，待批注）

### §4.1 A 块 · 中间背景

- **要什么**：一块不打断阅读、不抢素材封面的动效背景，铺在首页中部。
- **明确不要**（我的建议边界，待确认）：不要做成需要鼠标追逐的强交互（会在选素材时抢注意力）；不要铺满整个窗口（三栏结构里侧栏与详情栏应保持实色，否则文字可读性崩）。
- **硬约束**：必须**离线可用**、**零网络请求**；必须能在设置里关掉（复用已有 `settings.motionQuality` 三档，`App.tsx:488-491`）。
- **可复用结构**：`MaterialStage.tsx:650-689`（fixed 全屏 + `pointerEvents:none`）正是背景层要的形态；`MaterialBall` 的 `WebGLRenderer`（`:927`）已有现成上下文管理。
- **包体积红线**：three 静态引入 735KB→1905KB（`App.tsx:38-49` 注释），**必须懒加载**，不能进首屏主 chunk。
- **层级**：新背景层 z 必须 **≤40 且 <45**（`zStack.ts:32/41`），否则盖材质球。
- **待核实**：参考站的技术实现与零网络复现路径 → §6。

### §4.2 B 块 · 下方文件夹卡片

- **要什么**：首页下方一排「物种盒子」，有几种素材种类就有几个盒子；盒子有打开动效；点进去看到该种类的素材。
- **种类来源**：`KIND_NAV_ORDER` = **5 个**（`classify.ts:184-192`）—— 模型 / CAD / 材质组 / HDRI / 其他。图标可直接复用 `Sidebar.tsx:28-35` 的 5 个现成 Icon。
- **~~🔴 硬冲突（X-1）~~ → 已结案（Q-E 拍板 A，2026-11-09）**：`styles.css:9` 禁的是 `backdrop-blur` 与「渐变」；参考实现的磨砂是 `filter: blur` 复制层 + 同轮廓 `clip-path`，**不撞禁令**。允许用 `filter: blur` 做局部磨砂，`backdrop-filter` 继续全仓禁用（唯一例外仍是 `MaterialStage.tsx:556-562` 的 ultra 档舞台遮罩）。
- **关键设计问题（Q-A）**：盒子与左侧导航**双入口**，还是盒子**替代**导航、还是盒子只是「首页精选」不承载全量？
- **与 U-1 的关系**：2026-11-06 拍板「不新增第 6 个导航节点」是**左侧导航**的约束；首页盒子不改变导航节点数，不违反该拍板。但要防止实际效果变成「第 6 个入口」。
- **硬约束**：开盒动效要走已有动效质量档位（`motionProfile`，`shared/motionQuality.ts:38+`），低档位降级为直接跳转；`styles.css:619-944` 已有 `folder-tile-in/out` 与 `folder-stage-in/out` 的 smooth/ultra 两档实现，**B 块应当继承而不是新造**。

### §4.3 C 块 · 侧栏数据指标

- **要什么**：3 个示例指标 ——
  1. 新导入了几个模型（**能算**，用 `importedAt`，`types.ts:414`）
  2. 这个月我们整理了几个模型（**算不出来**，见下）
  3. 分类删除了几个素材（**算不出来**，见下）
- **「需要延伸」的落地形态（我的建议）**：指标不进 UI 硬编码，而是一个 `MetricSlot[]` 数组 + 一个 pure function 计算层；以后新增指标只加一条配置，不改组件。具体形态待架构师给，本文档只登记这个**约束**。
- **🔴 数据现实（§2.4 详述）**：
  - 数据库只有 `assets` / `backups` / `aliases` 三张表（`db.ts:113-116`），**无操作日志表**；
  - 硬删会物理删行（`store.ts:3336` / `:3501` / `:3532`），历史不可回算；
  - `updatedAt` 被收藏/评分/换封面污染（`store.ts:3631-3644`），**不能冒充「整理」**；
  - ⇒ 第 2、3 条**必须新开记账表、从零记账**，首日全 0。这是 Q-C 的核心。
- **侧栏插入点**：三个候选（`Sidebar.tsx:799-800` / `800-805` / `805-806`），我倾向 805-806 底部区顶端，待 Q-B 定。

**⚠️ 一个必须先说清的前提（决定 A 到底值不值）：**

模糊的观感只在**背后有东西**时成立。盒子带贴在底部、背后是纯色画布 —— **常驻态下 A 和 B 看起来几乎一样，糊一层纯色等于没糊**。A 真正吃到效果的时刻只有两个：

1. **hover 抬升**：卡片轻微上浮压到网格边缘，那一瞬间背后是素材封面，模糊有内容可糊。
2. **开盒动画**：盒子展开时覆盖住网格，展开面的磨砂才看得见 —— 这恰好就是你说的「有这样的打开动效」，也是这条需求的原点。

⇒ 结论：**A 的收益集中在动效里，不在静默态**。如果后面发现动效预算（`motionProfile` 低档位会降级为直接跳转）吃紧，A 和 B 的差距会进一步缩小。这条先记着，不是要改拍板。

### §6.2 两个效果的真实技术形态 —— 【查证】

| | particle-tide（A 块） | glass-folder（B 块） |

### §6.3 🔴 一条比报告更重要的发现：**glass-folder 根本不用 `backdrop-filter`**

我 grep 了 `src-glass-folder.ts`，全文件 `backdrop-filter` **只出现 1 次，而且是在注释里说明它为什么要避开**：

> `:36` 「Normal filtered content inside this clip avoids the browser's rectangular backdrop-filter surface under scaled 3D ancestors」

它的「磨砂」是这么做的（`:21`）：**复制一份同样的纸张层，套 `filter: blur(6px)`，再用同一个 `clip-path` 轮廓做遮罩**。

⇒ **这直接改写了我上一轮的判断（§2.6 X-1）。** 原来我以为「抄 glass-folder = 必须破玻璃拟态禁令」，实测是：它的手法**恰好就是禁令的正解**——不用 `backdrop-filter`，用「内容层自身模糊 + 裁剪」。`styles.css:9` 禁的是 `backdrop-blur`，不是 `filter: blur`。

同样地，渐变也不是问题：`grep -c gradient` → glass-folder 只有 1 处 `repeating-linear-gradient`，用来画纸上假的横线（ledger lines），不是装饰渐变；particle-tide **0 处渐变**。

⇒ **X-1 从「需求级冲突」降级为「一个需要写明边界的窄口子」**：允许 `filter: blur` 做局部恒温层，仍然禁 `backdrop-filter` 全局玻璃。Q-E 的问法要相应改（见 §5）。

### §6.7 小红书参考图结构分析（用户 2026-11-09 补发原图，Q-H 结案）

原图：`C:\Users\Administrator\Downloads\灵感分享｜简约清爽 B 端界面设计_6_灯野鹿设计_来自小红书网页版.jpg`。
内容是一张 DNA 分析进度仪表盘（1080×668）。**只看版式，不看内容**（用户口径）。

**它的实际构图（五块，逐块看）：**

| 位置 | 参考图里是什么 | 我们的对应物 |
|---|---|---|
| 最左 | **窄图标栏**（约 60px，纯图标 + 顶部头像 + 底部笔/头像） | **我们的侧栏是 216px 带文字** —— 参考图把导航压到极窄 |
| 顶部 | 大标题「DNA Analysis in Progress」+ 三个**状态数字**（剩余时间 00:32:15 / 已分析 642-1204 / 准确率 90.7%） | 我们中栏头是**筛选 chip 一排**（体积/分辨率/格式/时间/色标/风格/排序） |
| 中间 | **有机形状的柔和色块**（蓝绿 blob，不规则轮廓，占满主区） | A 块背景 |
| 底部 | **三张横排状态卡**（Completed 00:12:53 / In progress 00:24:38 / Pending 00:00:00） | B 块文件夹盒子 |

**三条会影响方案的事实：**

1. **「背景」在参考图里是静态图形，不是动效。** 它是一大块边缘柔和的不规则色域，看不出任何逐帧变化。用户给的第二个链接（particle-tide 粒子）才是动效。所以「背景」这个词在两条参考里指的不是同一样东西——**要么做成静态柔光色域，要么做成粒子**，这是 Q-K（下一轮问）。
2. **底部那三张不是「文件夹」，是状态卡。** 参考图里它们是并列的进度状态，没有「进入」语义。用户要的是「有几个种类就做几个文件夹」，即**带进入语义的容器**。所以 B 块不能照搬这张图的卡，只能借它的**排布节奏**（等宽、圆角、浅底、横向一排）。
3. **参考图的数据卡在右侧，不在左侧。** 用户说「侧栏给最近整理的文件数据」——但我们的**右栏被详情面板占着**（300px，`App.tsx:159`）。这是 Q-L（下一轮问）：数据指标放左栏（216px，窄）、还是右栏（要跟详情面板抢位）、还是像参考图那样做成主区的一部分。

**结论：这张图提供的是「留白大、层级少、卡片圆角大、导航极窄、数据成组」的版式语言，不能直接搬结构。** 我们的三栏比它多一栏，左右都被占用，硬套会撞车。
