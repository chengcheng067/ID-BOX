## 需求 A：主界面不显示知末模型名里的 `ID_xxxx` 段

**用户原话**：「在我们的主界面里面，不显示 ID 以及后面的数字部分。」

**现状**：知末下载包的内层文件夹名形如
`新中式复古仿古砖_复古砖_墙砖_地砖_深色仿古砖ID_1172815578`
（实测样本，见 `%APPDATA%\idbox\logs\app-2026-10-21.log`）。
导入时 `pickAssetName()` / 下钻层文件夹名会被 `sanitizeName(stripNoise(...))` 处理，
但**现有 `stripNoise` 不认 `ID_<数字>`** → 整段留在资产名里。

**落点（初步）**：`src/shared/naming.ts`
- `NOISE_PATTERNS`（第 23-29 行）加一条 `ID_<数字>` 剥离规则，例如
  `[/[-_\s]*ID[_\-]?\d+$/i, '']`（**仅供参考，需按真实样本核查**）。
- 风险点：`ID` 也可是正常词（如「ID卡」「ID牌」）→ 规则必须要求
  **`ID` + 分隔符 + 纯数字**、且位于**名称尾部**，否则误伤。
- ⚠️ 该函数同时决定**磁盘文件夹名**。改了会影响：
  ① 新导入资产的落盘名；② `rescan` 从目录名反推资产名；
  ③ `dedupeKeyOf()` 的重复检测键（历史记录的 key 用旧规则算出，新旧不一致会让
  同一资产在升级后被判成"不重复"）。**这是升级兼容性问题，必须单独评估迁移。**
- 更保守的替代方案：只改**显示层**（`Asset.name` 渲染时剥离），磁盘名不动 →
  零迁移风险，但界面上看到的和文件夹不一致。**两条路线开工前让用户拍板。**

## 需求 B：用 ID 去知末抓主图，作为模型封面

**用户原话**：「这个 ID 号我们可不可以拿来探索一下：用户把模型拖进来以后，
我们就跑一个自动化程序，去知末的网站上把这个模型的主图保存下来，作为我们的模型封面。」

**思路**：导入解析出 `ID_1172815578` → 拼知末详情页 URL → 抓 `og:image` / 主图 →
落盘为资产 `cover`。

**开工前要摸清的四件事（都还没做）**
1. **URL 规则**：ID 是否直接构成详情页路径（如 `znzmo.com/item/1172815578`）——
   需要实测几条真实 ID 验证，**不能凭猜**。
2. **反爬**：是否需要登录 cookie / 频控 / 验证码。若需要，得先问用户能不能接受
   "内置浏览器手动登录一次、之后复用 session"，这属于产品决策。
3. **封面优先级冲突**：现有封面四级回退是
   `skp 内嵌预览图 > 包内预览图 > 占位图标`（`src/main/importer.ts` P0-8/P1-2）。
   抓来的主图插在哪一级？建议 **低于 skp 内嵌预览**（内嵌图是 DCC 里的真实视图，
   主图是营销图）；但营销图通常更"好看"、更像卡片封面 → **需要用户拍板**。
4. **失败语义**：抓不到时必须静默回退到现有逻辑，绝不能让导入失败或卡住
   （网络是外部不可控依赖）。

**工作量预估**：不是一次小改——涉及"导入后置任务 + 网络 + 缓存 + 失败降级"，
建议单独一个迭代（0.6.x），先做**只对单条资产、手动触发**的探针版本验证 URL 规则，
跑通再谈批量自动化。
