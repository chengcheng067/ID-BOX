## 0. 先说结论（TL;DR）

1. **代码读不到**：`.rb` 共 107 个（包内 `dx_cloud_v2.12.14/`），其中 **106 个是加密分发**（RubyVault），只有加载器 `protected/loader.rb` 是明文；加上包根的入口 `dx_cloud.rb`，全包可读源码只有这两个文件。功能面靠**文件名、目录结构、明文 HTML、原生层字符串**反推，不是可读源码。连开源库 `rubyzip-1.2.1` 的 22 个文件都加密 → 防的是内容抽取，不是功能。
2. **它没有网络栈**：10 份原生二进制可打印串里**没有任何 http/socket/curl/reqwest/rustls/域名**（唯一的 http:// 是微软 SMI 命名空间 URI）。网络调用只可能发生在加密的 Ruby 层，逆向取不到端点。
3. **它不是"解密成明文再 eval"**：原生层有自定义 IR 符号（`ruby_ir_v1`、`RubyVaultIRFilterSyntax`、`@__rv_opcode` 等运行时槽）→ **把 Ruby 编译成自定义 IR、在原生层执行**。
4. **对 ID BOX 有价值的不是它的功能，是它的工程形态**（见 §2）：SHA256 指纹 + staging 原子落盘、按运行时分叉的原生件目录、可诊断的加载器错误码与日志、本地 HTML 参数面板、预置 skp + 属性字典驱动的参数化组件、自带 7z。
5. **不能照搬**：加密分发本身（我们分发的是明文 asar）、DPAPI + Ed25519 的鉴权密封（我们的口径是本地工具、无云端账号）。

## 3. 它的实现逻辑

### 3.1 入口与版本门槛（明文 `dx_cloud.rb`）

```ruby
if Sketchup.version.to_i < 21
  if UI.messagebox("当前SU版本过低...", MB_YESNO) == IDYES
    File.delete(__FILE__); Dir.glob(...).each { |i| FileUtils.rm_rf(i) }
  end
  raise('可搭鸭仅支持21及以上SU版本。')
end
module DX
  VERSION = [2, 12, 14].freeze
  WINDOWS_RUNTIME_CACHE_ROOT = 'C:/okducky/runtime'.freeze
  DX_EXTENSION = SketchupExtension.new('Okducky 可搭鸭', "dx_cloud_v#{S_VERSION}/core")
  Sketchup.register_extension DX_EXTENSION, Sketchup.is_pro?
end
```
元信息：官网 `home-plan.cn`，creator「斗西空间站」，版权「©2022-2026 上海家计划信息科技有限公司」。

### 3.2 Windows 中文路径兼容 → SHA256 指纹缓存

入口按 Ruby 版本分叉三对 `.darwin.bundle` / `.mingw.x64.so`，用 SHA256 算指纹 → staging 目录复制 + 逐文件校验 + `rename` 到 `C:/okducky/runtime/v<ver>/<digest>/`，再 `load`。这条路径的存在说明**SketchUp 在 Windows 上加载非 ASCII 路径的本地扩展会出问题**，所以它把文件搬到纯 ASCII 的缓存根再加载。

### 3.3 加密形态：AEAD 信封 + 自定义 IR 原生执行

文件头实证（`core.rb`，base64 解出）：

```
magic: RVLT1\0\0\0
{"format":"RVLT3","package_id":"f47658a458de2a72fafe9ac521eca24a",
 "sealed_manifest":{"ciphertext":...,"nonce":...,"tag":...},
 "wrapped_content_key":{"ciphertext":...,"nonce":...,"tag":...}}
<二进制密文 payload>
```
即「密封清单 + 包裹内容密钥」的信封结构，AEAD = **AES-GCM**（原生串：`invalid AES-GCM nonce or tag length`、crate `aes-0.8.4`、`sha2-0.10.9`），并校验 `plaintext_sha256` / `iseq_sha256`。

加载器（明文 `protected/loader.rb`）：

```ruby
module RubyVaultLoader
  SUPPORTED_RUBY_SERIES = %w[2.7 3.2 3.4].freeze
  def boot
    return true if RubyVaultRuntime::API_VERSION >= 8
    require native_require_path            # 按 ruby_series + darwin/mingw.x64 选 stem
    RubyVaultNative.bootstrap
  rescue LoadError => e then fail_once(native_files_present? ? "RVL-102" : "RVL-101", e)
  # 系列/平台不符 → RVL-103
end
```

原生层符号 → 关键判断：**它不把源码解成明文再 eval，而是把 Ruby 编译成自定义 IR 在原生层执行**：
`RubyVaultRuntime` / `RubyVaultNative` / `bootstrap` / `load_text_file` / `rv_open_bytes` / `rv_open_runtime` / `Init_rubyvault34`、IR 符号 `RubyVaultIRFilterSyntax`、`RubyVaultIRMethodSyntax`、`ruby_ir_v1`，运行时注入槽 `@__rv_name_id`、`@__rv_arg_nodes`、`@__rv_simple_args`、`@__rv_opcode`、`@__rv_hash_key`、`@__rv_filter_syntax`、`@__rv_case_syntax`、`@__rv_native_body_syntax`。

### 3.4 鉴权：本地密封，无网络栈

原生层有 `dx.auth_cache_*`、`dx.encrypt_number` / `dx.decrypt_number`、`YummyEncoder/auth-cache-v2/windows/{1,2}`、前缀 `DXAUTH2:`、Windows DPAPI 错误串、`embedded Ed25519 key`、SPKI/ASN.1 DER 解析错误串 → 鉴权缓存是「本机 DPAPI + 硬编码 Ed25519 公钥」的本地密封。全量二进制无网络栈 → 网络调用只在加密 Ruby 层（Ruby 标准库或外部进程），逆向无法取到端点。

### 3.5 UI 桥接

`UI.start_dialog` 形态的本地 HTML + 单向回调桥（见 §1）。空目录 `diagnostics/`、`temp/thumbnail_file/` 是运行时落地目录 —— 说明它有封面/缩略图落盘逻辑，与 ID BOX 的封面管线同类。

## 4. 顺带回答 `docs/36` 的开放问题（按本次逆向结论）

| # | 问题 | 逆向给出的答案 |
|---|---|---|
| Q2（协议形态） | 三选一 | 可搭鸭用**进程内回调桥**（同一进程，无跨进程协议）。它印证了：**跨进程部分它没有**——它的"接口"就是 Ruby 直接调 SketchUp API。所以 ID BOX 若要给外部进程用，必须自己造协议层；三选一里 `HTTP + JSON` 仍是推荐（可搭鸭无网络栈这一事实不构成反证，因为它压根没有跨进程需求）。 |
| Q3（鉴权） | 要不要 token | 可搭鸭用**硬编码 Ed25519 公钥 + 本机 DPAPI**，属商业防破解，不适合我们。本地工具口径不变 → 仍按 `docs/36` 推荐「token + 默认关」。 |
| Q4（取用语义） | 给路径 vs 主动 push | 可搭鸭是**主动 push**（Ruby 里直接 `import` 组件）。它的经验：push 体验更好但强耦合，且必须运行在它自己的进程里。ID BOX 若走插件，插件进程由 DCC 承载 → 建议仍按 A（给路径），把 push 留给插件侧自己做。 |
| Q6（Blender） | — | 无新证据，维持不写死。 |
| 新增 | 插件包目录约定 | 采纳它的做法：按运行时版本分叉目录 + 指纹校验 + 纯 ASCII 缓存路径（Windows 非 ASCII 路径确实会出问题）。 |
| 新增 | 可诊断性 | 采纳：错误码 + 结构化 loader 日志 + 用户可见诊断页。 |
