## 2. T02：`commit(patch, reason)` 单一调度 + 重绘矩阵

### 2.1 为什么做（一句话）

现在 `activeKind` 有 4 处赋值、`activeCategory1` 有 6 处、`sortKey` 有 3 处，每处后面都手抄一遍 `renderSide(); renderChips(); renderList(); renderCount();` —— 改一个地方漏一处就出现「筛选变了但列表没变」。T02 把所有写入收进**一个函数**，重绘范围由**一张表**决定。

### 2.2 分三步做（每步都能独立验证，不要合并）

#### 第一步：加壳（行为完全不变）

在 `nextIn` 函数附近（`1720` 左右）新增：

```js
  /* 重绘矩阵：哪些原因需要重绘哪些区域。true = 重绘。
     原则：改筛选 → 左栏高亮 + chips + 列表 + 计数都要变；
           改排序 → 只影响列表顺序，不动左栏和计数；
           改搜索词 → 只影响列表和计数。 */
  var REDRAW_MATRIX = {
    kind:     { side: true,  chips: true,  list: true,  count: true },
    category1:{ side: true,  chips: true,  list: true,  count: true },
    category2:{ side: true,  chips: true,  list: true,  count: true },
    sort:     { side: false, chips: true,  list: true,  count: false },
    query:    { side: false, chips: false, list: true,  count: true },
    reset:    { side: true,  chips: true,  list: true,  count: true },
    density:  { side: false, chips: false, list: true,  count: false },
    view:     { side: false, chips: false, list: true,  count: false },
    select:   { side: false, chips: false, list: false, count: false }
  };

  /* 唯一的 state 写入入口。patch 里放要改的字段，reason 决定重绘范围。 */
  function commit(patch, reason) {
    if (patch) {
      for (var key in patch) {
        if (Object.prototype.hasOwnProperty.call(patch, key)) {
          state[key] = patch[key];
        }
      }
    }
    var plan = REDRAW_MATRIX[reason] || REDRAW_MATRIX.reset;
    if (plan.side) { renderSide(); }
    if (plan.chips) { renderChips(); }
    if (plan.list) { renderList(); }
    if (plan.count) { renderCount(); }
  }
```

**这一步不许改任何调用点。** 只为下一步做准备。

## 3. T03：左栏三级树 + `activeCategory2` + 哨兵 + 空态

### 3.1 为什么做（一句话）

用户要「一级 / 二级菜单的触发和 ID BOX 主软件一样」，而插件现在**只有一级**，二级数据存在但只当搜索字段用。

完成后的语义（必须和主软件逐条一致）：

| 动作 | 结果 |
| --- | --- |
| 点大类 | 设 `activeKind`，清掉一级/二级，展开该大类的一级树 |
| 点一级 | 设 `activeCategory1`，**展开它的二级树**，清掉二级 |
| 点二级 | 设 `activeCategory2`（一级保持不变） |
| 再点同一个二级 | 取消二级（一级仍保留） |
| 再点同一个一级 | 取消一级（大类仍保留） |
| 再点同一个大类 | 回「全部」 |

**渐进披露**（用户 2026-11-10 拍板 D05）：只给「有 ≥1 个真实二级值」的一级画展开箭头和二级行；没有真实二级值的一级仍然只有一行、不可展开。

### 3.2 九个小步（严格按顺序，每步单独验证）

#### 第 1 步：`state` 加两个字段

`panel.html:617-634` 的 `state` 对象里，在 `activeCategory1: ''` 下面加两行：

```js
    activeCategory1: '',
    activeCategory2: '',   /* 二级分类；'' = 不筛选 */
    expandedL1: '',        /* 当前展开了哪个一级的二级树；'' = 都不展开 */
```

验证：面板照常打开，无报错。

#### 第 2 步：新增 `isUnclassified()`（哨兵统一判据）

**为什么必须加**：索引里的「未分类」是**字符串 `'未分类'`**，不是 `null`（主程序 `pluginSnapshot.ts:258-259` 就是这么写的）。现有 `matches()` 只判「空字符串」，而 `topCategories` 用的是「空 → 显示为未分类」，两套口径不一致，导致「节点计数 N、点进去 0 条」。

在 `textOf`（`678`）下面加：

```js
  /* 「未分类」的统一判据：空串 / null / 字面「未分类」都算未分类。
     ⚠️ 必须用它判定，不要各写各的 —— 索引里的空分类是字符串 '未分类' 而不是 null。 */
  function isUnclassified(value) {
    var text = textOf(value).trim();
    return text === '' || text === UNCLASSIFIED_LABEL;
  }
```

#### 第 3 步：`matches()` 改一级判定 + 加二级判定

现在（`1104-1122`）一级判定写的是 `if (category1) return false`（只认空串）。改成用 `isUnclassified`，并追加二级：

#### 第 4 步：新增 `secondCategories(kindKey, category1)`

放在 `topCategories`（`1280`）下面。**关键：必须用 `groupRecords()`（内部走 `scopedRecords()`），不许用 `state.data.records` 全量。**

```js
  /* 某个大类 + 某个一级下，真实存在的二级值（含计数）。
     排序沿用 topCategories 的口径：未分类恒最后、其余按计数降序、同数按名称。
     ⚠️ 聚合范围必须是当前大类 + 当前一级，不能全库 —— 模型侧和材质侧的二级值不重叠，
        跨类聚合会造出「点进去 0 条」的假节点。 */
  function secondCategories(kindKey, category1) {
    var key = (kindKey === undefined) ? state.activeKind : textOf(kindKey);
    var l1 = textOf(category1).trim();
    if (!key || !l1) { return []; }

    var records = groupRecords(key);
    var counts = {};
    for (var i = 0; i < records.length; i += 1) {
      var row = records[i];
      if (textOf(row.category1).trim() !== l1) { continue; }
      var raw = textOf(row.category2).trim();
      /* 关键：哨兵不生成二级节点，否则会多出一个叫「未分类」的假分类 */
      if (isUnclassified(raw)) { continue; }
      counts[raw] = (counts[raw] || 0) + 1;
    }

    var list = [];
    for (var label in counts) {
      if (Object.prototype.hasOwnProperty.call(counts, label)) {
        list.push({ name: label, count: counts[label] });
      }
    }
    list.sort(function (a, b) {
      if (b.count !== a.count) { return b.count - a.count; }
      return a.name.localeCompare(b.name);
    });
    return list;
  }
```

#### 第 9 步：空态文案按筛选来源分支（§3.6）

找那段（`grep -n "没有匹配" panel.html`），替换成：

```js
    /* 空态文案按「为什么空」分支：查询词优先，其次分类筛选。
       ⚠️ 分类筛选时 query 是空的，直接拼会显示「没有匹配「」」。 */
    var q = state.query.trim();
    var hasFilter = !!(state.activeKind || state.activeCategory1 || state.activeCategory2);
    if (q) {
      empty.appendChild(make('div', 'empty-lead', '没有匹配「' + q + '」的记录'));
      empty.appendChild(make('div', 'empty-text', '换个关键词，或点上方「清除筛选」回到全部。'));
    } else if (hasFilter) {
      empty.appendChild(make('div', 'empty-lead', '这个筛选下没有素材'));
      empty.appendChild(make('div', 'empty-text', '换个分类，或点上方「清除筛选」回到全部。'));
    } else {
      empty.appendChild(make('div', 'empty-lead', '没有可显示的素材'));
      empty.appendChild(make('div', 'empty-text', '在 ID BOX 里导入素材后，回到这里点「刷新」。'));
    }
```

并在空态里加一个「清除筛选」出口（`data-role="empty-clear"` 的 button，点击走 `commit({...全清}, 'reset')`）。事件绑在 `#empty` 上，用 `closestWithAttr` 找。

验证：挑一个空分类（或先搜索一个不存在的词）→ 文案不再是「没有匹配「」」；点空态里的「清除筛选」→ 回到全部。
