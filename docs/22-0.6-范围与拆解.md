## 3. 逐项拆解

### 3.1 贴图分辨率筛选
- **采集**：图片宽高在**主进程**读文件头（JPEG 的 SOF0/SOF2、PNG 的 IHDR），不整图解码
  → `shared/imageSize.ts`（纯函数，可单测）。导入（`importer.ts`）与重扫（`rescan.ts`）时写进 `AssetFile`。
- **存储**：`AssetFile` 加可选 `w?: number; h?: number`（可选 = 旧数据不用迁移，缺失就是"未知"）。
- **筛选**：`Filters` 加 `minResolution: ResolutionBucket | null`；`matchesFilters` 里按「长边 ≥ 2048 / ≥ 4096」判断；中栏头加一个 chip（与体积/时间同族）。
- **UI 文案**：「2K 以上」「4K 以上」，未知分辨率的资产**不进**这两档（并在 tooltip 说明）。

### 3.2 智能集合（保存筛选视图）
- 侧栏「整理」组下方新增「智能集合」组：列出 `settings.savedViews`，点击套用 `filters + sort`。
- 中栏头「＋ 保存当前筛选」→ 输入名字 → 存进 settings（上限 20，超出提示先删）。
- 删除：悬停出现 ✕（二次确认不需要，删的是视图不是资产）。
- **不改磁盘结构**，纯虚拟视图（与 `docs/13` F-06 的判定一致）。

### 3.3 别名映射表
- `shared/aliasRules.ts` 的 `resolveDisplayName(asset, index)` 已支持「资产级 > 全局键 > 原名」。
- 缺的是：① 从 `settings.aliases` 建索引（memo，settings 变了才重建）；② `displayName()` 走索引；③ 设置页的表格 UI（增删改 + 导入/导出 JSON + 「一键采纳建议」用 `aliasSuggest`）。
- **只影响显示**：磁盘文件名一个字都不改（用户明确要求过）。

### 3.4 批量重命名 / 命名模板（风险最高）
- 模板占位符：`{name}` `{c1}` `{c2}` `{year}` `{n}` / `{n:2}`（`shared/renameTemplate.ts`，纯函数 + 单测）。
- **⚠️ id 口径更正（2026-10-22 由 rename-engineer 校准，以代码为准）**：
  `Asset.id` **不是** relFolder，而是 **UUID** —— `importer.ts:356/607` 与 `rescan.ts:243` 都是
  `randomUUID()`；`db.ts` v2 迁移专门把旧库的 `id = relFolder` 换成了 UUID。
  所以**改名不改 id**：`bulkPut` 原地覆盖即可，`selectedIds` / `folderViewAssetId` /
  `settings.aliases(scope:'asset')` / `aliasOverride` / 球图 `<id>-<hash>` 全部天然存活。
  （本文件早先写的「改名等于换 id」是错的，已按代码更正。）
- **执行面**：只改**资产文件夹名**（不动包内文件）。缩略图必须 regen（封面绝对路径变了 → salt 变），
  且**材质球图要跳过 regen**（球图名只由 id+槽位 hash 决定，与目录无关）。
- 安全：零写入预检（库内/父目录相同/批内重名/保留名/目标已存在）→ 任一失败整批不动 →
  逐条 `fs.rename`（仅 EXDEV 退化 cp+rm）→ 任何一条失败**逆序反向回滚**。
- 第一版范围：多选浮动条上的「重命名…」+ 预览表；单条重命名沿用既有 `renameAsset`。

### 3.5 大库性能
- 现状：虚拟滚动已有；需要的是**实测**：生成 2000 / 5000 / 10000 条假资产 → 量首屏渲染、滚动 FPS、筛选耗时。
- 已知热点：`useVisibleAssets` 每次筛选全量 map；`countLevel1/2` 遍历全量；侧栏计数。
- 加固手段（按需，不预设）：筛选结果缓存（filters 引用不变就复用）+ 计数按 kind 预聚合 + 网格行高缓存。
