| **F-2** | 导出选项只有「带上环境光贴图（包会更大）」一个固定开关——文案看不懂（用户称"导出光环"），且逻辑是按体积给 HDR 开小灶 | **按库里实际存在的大类动态生成勾选项** | 检测库中实际存在的 `AssetKind`，有几类给几个勾选项（用户例：只有模型+贴图→2 项；模型+贴图+CAD+HDR→4 项）；HDR 就叫 HDR，不再单独特殊对待；默认全选。**推翻 Q-7 的「HDR 单独勾选」口径**。实现上导出契约 `includeHdri:boolean` 改为「大类集合」，过滤/白名单/manifest 同步改 |

| **F-4** | 第二次装机点导出仍失败，提示「操作未完成，请稍后重试」 | 用户授权直接查日志定位 | **真因：打包时漏了一个依赖模块**。日志 `app-2026-11-23.log:417` 抓到 `package:export-failed` → `Cannot find module 'archiver-utils'`，Require stack 指向 `app.asar\node_modules\zip-stream\index.js`。逐包清点 app.asar：131 个运行时包里 `archiver` / `zip-stream` / `compress-commons` / `readdir-glob` / `tar-stream` 都在，**独缺 `archiver-utils`**（archiver 与 zip-stream 的传递依赖）。electron-builder 的 node_modules 收集器把它漏掉了，而 dev 模式直接读磁盘 node_modules，所以 4943 条测试全绿也测不出来。修：① `package.json` 把 `archiver-utils@^5.0.2` 提为**直接依赖**（根依赖必定被收集；实测 `build.files` 里显式写 `node_modules/archiver-utils/**` 无效，node_modules 不走 files 匹配）；② 新增 `scripts/verify-deps.cjs`（`npm run verify:pack`）——把 asar 解到临时目录，对每个包声明的 `dependencies` 逐条 `require.resolve`，专抓这种「库内部互相 require 缺包」；已用坏包/好包双向验证（坏包准确报出 `zip-stream -> archiver-utils@^5.0.0`，好包通过）。 |

**F-4 修完的交付包**：`release/IDBOX-Setup-1.1.0.exe`（88,318,309 B，SHA256 `895e970593c0417e77e16e7e638a0e49b437d3dcb4cf4fd3c4be22af94d2080e`），出包后 `npm run verify:pack` 在 194 个包 / 188 条依赖边上全部可解析。版本号仍是 1.1.0（未对外发布过，属同日重出）。

**为什么这类事故能溜过全部测试**：单测跑的是磁盘上的 `node_modules`，路径永远齐；只有 asar 内的树才可能缺件。因此从 1.1.0 起，出包流程固定为 `build → electron-builder → npm run verify:pack`，不跑最后一步不算出包完成。

## 7. 插件安装判据重做（2026-11-23，用户追问「插件出新版了但显示已安装」）
