## 0. 一句话与判据

**一句话：以溜云库/青云库/Eagle 为镜子，盘点 ID BOX 的功能缺口，把"值得抄的"和"绝不能抄的"分开，给你一份 v0.3 可拍板的小步清单。**

三条判据（全文所有判断都用这三把尺子量，先立在这）：

| # | 判据 | 出处 |
| --- | --- | --- |
| J1 | **库的归属权是差异化本体**：任何功能若让库"离开软件不可用 / 需要登录 / 绑定某站"，一票否决 | PRD v1.1 §2.3.3 |
| J2 | **MVP 小步走**：v0.3 候选 3–5 条封顶，每条都要能独立验收 | 用户工作方式 |
| J3 | **它们赢在素材多（供给侧），我们不做供给**：所有"给用户更多素材"的方向都不碰 | PRD §9 Scope Out |

成本量级口径：**S** ≈ 1–2 天（纯渲染层/纯逻辑）；**M** ≈ 3–5 天（动主进程或 Dexie 迁移）；**L** ≈ 1 周+（新依赖 / 新服务端 / 大迁移）。预研阶段只给量级，不给工时承诺——精确估算归架构师。

## 1. 功能维度拆解（六个维度 × 三态）

> 三态含义：🅐 竞品有 · 我们没有（缺口）；🅑 竞品有 · 我们已有（打平）；🅒 双方都无（蓝海，可以做我们的差异点）。
> "我们"的现状以 `docs/09` M1–M7 功能清单 + v0.2.2 出包内容为准。

### A. 入库自动化

| 态 | 功能 | 说明 |
| --- | --- | --- |
| 🅑 | 拖入→解压→分类→清包 | 我们有（GBK/预检/杂质剔除/智能命名/原包三档，M1）；溜云库/青云库都有 |
| 🅐 | **批量 AI 智能识别**（溜云库） | 批量添加时 AI 识别品类归档。我们对应物是词表匹配（保守防误伤，v0.2 实测自动落对约 1/3）——见 F-02 |
| 🅐 | **重复检测**（青云库） | 导入时对重复资产提示。我们 PRD P1-5 已立项未实现——见 F-01 |
| 🅒 | **杂质剔除**（微信扫码图 / 说明 txt / site 文件自动清） | 溜云库/青云库文档均未提及此能力；这是我们从真实知末包结构里长出来的，**蓝海** |
| 🅒 | **下载目录监控**（自动接管新下载） | 两家竞品都靠"从自家站内下载"绕过了这个环节（它们本来就在下载侧）；我们靠它吃**任何站**的下载——**这是中立性差异点**，PRD P1-1 已立项（默认关） |

### B. 检索与发现

| 态 | 功能 | 说明 |
| --- | --- | --- |
| 🅑 | 关键词搜索 / 标签 / 分类筛选 / 排序 / 双视图 | 我们有（M3）；Eagle 是标杆 |
| 🅐 | **多维组合筛选**（Eagle 强项）：按文件大小 / 导入时间 / 分辨率等数值区间叠加 | 我们目前只有单轴筛选+排序——见 F-03 |
| 🅐 | **收藏 / 评分 / 颜色标注**（溜云库收藏、Eagle 评分+色标） | 见 F-04 |

| 🅐 | **以图搜图**（溜云库） | 见 F-09 |
| 🅒 | **「未分类哨兵」视图**（分类没把握的资产集中在一处等人指派） | 竞品靠 AI 硬猜，我们"宁可漏不错"+哨兵收口——这是"防误伤"取向的蓝海配套（已随 06 体系落地，此处备案） |

### C. 预览与元数据

| 态 | 功能 | 说明 |
| --- | --- | --- |

## 2. 候选功能池（14 条，逐条可批注）

> 每条格式：**功能描述 ｜ 竞品出处 ｜ 用户价值 ｜ 成本 ｜ 风险 ｜ 与差异化定位的关系**。
> 「关系」三档：🟢 增强中立性 / ⚪ 中性 / 🔴 危险·会滑向绑站。
> 已在 PRD 需求池的标「见 PRD P1-x」，不重复立项，只补增量判断。

---

**F-01 重复检测（导入时提示）** ⚪ ｜ 成本 S
已有同名/同内容资产时，导入前提示「已存在，跳过/仍导入/两者都留」。
出处：青云库。价值：设计师隔几周忘了下过，GB 级重复最烧盘。
风险：低；判定口径要克制（只做文件名+包名归一化，不做内容哈希——见 PRD P1-5 与 T6 取舍）。
**状态：PRD P1-5 已立项，本轮无需重立项，只是建议**提级进 v0.3**（理由见 §4）。

**F-02 词表"尾字族"构词（分类准确率迭代）** 🟢 ｜ 成本 S–M
`衣柜/橱柜/书柜/电视柜 → 柜子`、`餐桌/书桌 → 桌子` 这类派生词，靠"尾字归并"吃进一级分类。v0.2 实测 62% 漏分里这是最大一块（docs/08 §5.2 / DEF-16）。
出处：溜云库"批量 AI 识别"的对位物——我们不用 AI，用词表构词法，**误伤面可控、全程可解释**。
风险：中低；`玄关柜` 到底归柜子还是玄关类，要词表裁定，须走架构师流程（已在办：task #31 挂账）。
**状态：DEF-16 已挂账待裁定。本轮建议：裁定通过即进 v0.3。**

**F-03 检索增强：数值区间 + 组合筛选** ⚪ ｜ 成本 S–M
在现有 分类/风格/关键词 三轴之上，叠加：文件大小区间、导入时间区间、贴图分辨率档（≥2K/≥4K）、SU 版本。
出处：Eagle 的核心强项。
价值：资产过 500 后，"上次那批 4K 的木纹贴图"这类问题才能一句话筛出来。
风险：低；UI 密度要克制（符合 docs/11 的安静审美，筛选器默认收起）。
**状态：PRD P1-3（分辨率）已立项；大小/时间区间为本轮新增增量。**

**F-04 收藏 / 评分 / 颜色标注** ⚪ ｜ 成本 S
资产级 ⭐ 收藏（或 1–5 评分 / 颜色标），侧边栏加「收藏」入口。
出处：溜云库（收藏）、Eagle（评分+色标）。
价值：设计师"常用的那把椅子"是高频心智——收藏是成本最低的运营维度。
风险：低；Dexie 加字段 + 迁移，注意向后兼容（用户重视）。
**状态：新增候选。**

**F-05 对比视图** ⚪ ｜ 成本 M
勾选 2–4 个资产并排比封面/参数，犹豫不定的素材比完再定去留。
出处：溜云库「对比」。
价值：真实场景存在（同一沙发三家版本），但频次存疑——用户自己是唯一裁判。
风险：低；主要是 UI 工作量。
**状态：新增候选，建议先进观察池。**

**F-06 智能文件夹（保存的搜索）** ⚪ ｜ 成本 M
把一组筛选条件存成命名视图（如"奶油风贴图 4K"），侧边栏常驻。
出处：Eagle。
价值：把"每次重新筛"变成"点一下"；与四层目录不冲突（虚拟层，不动物理目录）。
风险：中低；注意它**不改磁盘结构**，不违反 J1。
**状态：新增候选。**

**F-07 局域网共享 / 团队库** 🔴 ｜ 成本 L
出处：溜云库企业版、青云库局域网共享。
**本轮判断：不做。** 会引入账号/服务端/权限模型，J1 一票否决；且用户当前单机（PRD S9 已覆盖）。
**保留在池里的唯一理由**：留档备查，防止未来有人说"竞品都有"时没有书面依据。

**F-08 云同步 / 多设备** 🔴 ｜ 成本 L
出处：溜云库云同步。
**本轮判断：不做。** 同 J1。用户是"数据敏感、本地优先"画像，云同步在他的需求里是负分项。
**与 F-07 同理留档。**（如果未来要做，正确形态也是"用户自己的网盘目录做文件层同步、我们不管元数据"——那也不需要我们写服务端。）

**F-09 以图搜图（库内）** ⚪ ｜ 成本 L
在本地库里"传一张图找相似资产"。
出处：溜云库。
**本轮判断：观察池。** 理由：①本地图库规模（数百资产）下，关键词+封面墙的命中率已经够；②本地做相似度检索要么引入 embedding 模型（体积/复杂度暴涨，违反轻量底线），要么降级成颜色直方图（效果一般）；③溜云库的以图搜图本质是在它的百万素材池上做的——**那是供给侧能力，我们跟它比这个必输**（J3）。
**复评条件**：资产规模破 5000 或用户主动提出。

**F-10 MAX 版本 / 渲染器元数据识别** 🟢 ｜ 成本 S–M
对 `.max` 资产读文件头识别 3ds Max 版本；渲染器（CR/VRay）可从包内文件名/配置文件嗅探。
出处：青云库（识别 MAX 版本/渲染器）。
价值：与已上线的 SU 版本解析（P0-15）对称补齐；用户 D5 工作流拿到的 max 源包越多越有用。
风险：低；max 是 OLE 复合文档，读版本串有公开资料，但失败必须静默降级。
**状态：新增候选，v0.3 有位置就带上。**

**F-11 批量改名 / 批量移动** ⚪ ｜ 成本 M
出处：溜云库批量操作。
**本轮判断：维持 PRD T7 的 Scope Out。** 命名已有"包内根目录名+去水印+防重"，事后批量改是危险的批量写操作，收益低。竞品有 ≠ 我们该有。

**F-12 MAX 内部插件 / 脚本库** ⚪ ｜ 成本 L
出处：溜云库从 MAX 内部添加、MAX/SU 脚本库。
**本轮判断：不做。** 用户主力是 SU + D5，不是 MAX（PRD S7 已裁定）；且插件要跟各软件版本矩阵做兼容维护。等 M4 拖出（SU/D5）真实跑顺后，若用户提出"在 SU 里想直接开库"，正确形态也是先评估 **SU 侧**入口，且那是另一个立项。

**F-13 词表可配置 / 热更新** 🟢 ｜ 成本 M
让用户能自己增改分类词表（06 §7.2 判定"低频但必然发生"），格式用 06 已有的级联枚举，校验复用 `normalizeCategoryPair`。
出处：竞品无（它们的词表是闭源的）——**蓝海**。
价值：把"分类不对"的最终解释权交给用户，而不是逼用户等我们更新；**中立性的极致形态是可定制**。
风险：中；要做好"改坏了如何回滚"（默认词表备份 + 一键还原）。
**状态：06 §7 已评估过三方案，本轮建议排 v0.3 之后（v0.4），先把尾字族（F-02）跑顺。**

**F-14 PBR 包元数据源扩展（Beyond AmbientCG）** 🟢 ｜ 成本 M–L
AmbientCG/Crystal 的 `.json` 语义标签直读已拍板；此条是把"权威名称源"思路扩到更多材质包来源（PolyHaven、ShareTextures 等各家的 json/元数据格式）。
出处：竞品无——**蓝海，且直接强化我们材质类的独门能力**。
风险：低；纯解析层扩展，失败静默降级到文件名。
**状态：新增候选，建议观察池（等用户补更多 Crystal 样本、边界校准完再说）。**

## 3. Scope Out 复核（竞品视角过了一遍）

PRD §9 十条维持不变，竞品调研后**新增/强化三条**：

| # | 项 | 复核结论 |
| --- | --- | --- |
| S11 | **云渲染 / VR 全景合成** | 溜云库的招牌，但纯属供给侧重资产（768 线程是要真金白银烧的服务器）。J3 一票否决。**竞品有，恰恰说明我们不该有** |
| S12 | **自有素材供给 / 在线素材站对接**（含知末官方 API 对接） | 同 J3；且对接站点 API 等于把中立性卖掉——我们吃的是"任何站的包落地之后"，一旦只对某站优化就开始滑向溜云库 |
| S13 | **AI 自动打标（模型侧）** | 溜云库"批量 AI 识别"看似诱人，但代价是要么联网调模型（违反 J1），要么本地塞模型（体积/复杂度）。我们的路线是**词表 + 构词法 + 用户哨兵指派**——慢一点但可解释、可修正、零依赖。这条钉死，防止未来被"AI 化"带偏 |

## 4. 迭代排期建议

### v0.3 候选（4 条，按建议顺序）

| 顺序 | 编号 | 功能 | 成本 | 为什么排这个位置 |
| --- | --- | --- | --- | --- |
| ① | **F-02** | 词表尾字族构词 | S–M | **杠杆最高**：v0.2 实测 62% 漏分里它是最大一块；资产库越攒越多，分类准确率的价值随时间复利。且 DEF-16 已挂账、流程已走到架构师裁定（task #31），顺势收口即可，不新开战线 |
| ② | **F-01** | 重复检测提示 | S | 导入体验闭环的最后一块：GB 级重复是真实烧盘痛点，成本小、无 UI 复杂度，PRD P1-5 现成设计 |
| ③ | **F-03** | 检索增强（大小/时间/分辨率区间） | S–M | "找得到"是主战场（PRD §2.2.2），资产过几百后现有单轴筛选会先感到吃力；分辨率档顺带收掉 P1-3 |
| ④ | **F-04** | 收藏/评分 | S | 资产运营维度从零到一的最小步；Dexie 加字段小迁移，顺带演练一次向后兼容迁移流程（用户重视） |

> 备选第 5 位：**F-10 MAX 版本识别**（S–M）——若上面 4 条有被砍的，它顶上；若不砍，让 v0.3 保持 4 条，符合 J2。

### 观察池（不排期，触发条件明确）
