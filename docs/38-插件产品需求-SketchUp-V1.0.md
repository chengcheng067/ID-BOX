## 1. TL;DR（5 条）

1. **V1.0 插件 = SU 里的一个本地面板：搜词 → 列表 → 点一下即插入。** 不做面板内真拖（§5 用户裁定 + SketchUp issue #506 事实），真拖列入「明确不做」。
2. **数据通道主选 ③ `file://` 索引 JSON（文件 + 文件监视），① HTTP 作补充。** 这是用户 2026-11-04 拍板，**与 `docs/36 §4.5 / Q2` 的推荐相反**，本文按用户口径写，并在 §6.1 显式标记为对 `docs/36` 的偏离。
3. **V1.0 实际只需要两个文件**：`manifest.json`（发现文件：库根、apiVersion、生成时间）+ `index.json`（资产快照）。`docs/36` 的 5 个端点里，**E1/E2 降级为文件读取，E3 并入 E2，E4/E5 不进 V1.0**（§4）。
4. **插件是明文、无网络、无原生件的薄壳**：入口 `.rb` + 本地 HTML 面板；不加密（`docs/37 §2` 明确不可照搬）、不解压（只取用**已入库**资产）、不联网、不遥测。
5. **来源回溯靠属性字典 `idbox_*`，不写绝对路径**：写 UUID 主键 + 相对路径（`docs/01 P0-7` UUID 稳定主键；`docs/36 §5.3` 路径非稳定契约）。

## 2. 定位与边界

### 2.1 一句话定位

> **插件是 ID BOX 的"延伸面板"，不是第二个库。** 索引、分类、封面、缩略图的唯一权威仍在 ID BOX；插件只读快照、只负责"在 SU 里搜到并插入"。

### 2.2 三把尺子（沿用 `docs/13:18-24` 与 `docs/36:20-27`）

| # | 判据 | 出处 |
| --- | --- | --- |
| J1 | **本地优先、数据不出本机**：插件不得有网络栈、不得有账号、不得上传任何路径清单 | `README.md:217`；`docs/25:2132`（原文在 `:2220`）；`docs/13:20`（库归属权一票否决） |
| J2 | **稳定契约优先于数据完整性**：插件只依赖"搜词 → 路径"这一层，不依赖 Dexie schema | `docs/25:2115`（原文 `:2203`）；`docs/16:100`（`folder` 无一致性保证者）；`docs/36 J2` |
| J3 | **MVP 小步、只读优先**：一个 DCC、能独立验收、写操作最后开 | `docs/13:21`；`docs/25:2105`（原文 `:2193`） |

### 2.3 与既有能力的关系（不重复造）

| 既有 | 口径 | 与插件的关系 |
| --- | --- | --- |
| **系统级拖出到 SU/D5**（`docs/02:63` ④K6、`src/shared/ipc.ts:42-48`、`README.md:196`） | 一次性交互，不是接口（`docs/25:2225`） | **保留不动**。插件解决的是"不想切回 ID BOX 找"（`docs/25:2226`），两者共存、互不替代 |
| Windows 资源管理器 → SU 视口拖文件 | 可用（`.skp`／图片／往材质槽拖贴图），**前提 SU 不以管理员运行** | 属用户既有工作流，插件**不必重造**；插件的价值是"搜"，不是"拖" |
| 缩略图/封面落盘（`Asset.thumbPath`、`cover`，`src/shared/types.ts:305-311`） | 本地文件 | ③ 形态下面板显示缩略图**不需要任何端点** —— 直接读本地文件（这是 ③ 相对 ① 的额外好处，见 §6.1 偏离3） |
| SU 版本元数据（`suVersion`/`suMajor`，`docs/01 P0-15`） | 已有、低成本 | 插件插入前做**版本兼容预警**：文件版本高于运行 SU 会失败（`docs/36 §6 P3` 风险③） |

### 2.4 版本门槛（建议默认，待并入 D3）

`UI::HtmlDialog` 需较新版本（`docs/36:128` 已查证该类存在）；可搭鸭的实测经验是 **SU < 21 直接拒绝**（`docs/37:75-80`）。**建议 V1.0 门槛 = SketchUp 2021+**，明确不承诺 2014（库内存在 `sketchup 2014` 版本记录是**素材的上传版本**，`docs/25:164`、`:184`，不等于用户运行的 SU 版本）。老版本降级方案（`UI.start_dialog`，可搭鸭用的形态，`docs/37 §1`）**【待核实】**，不进 V1.0。

### 3.3 明确不做（写死）

1. **面板内真拖** —— 用户 2026-11-04 裁定「点一下即插入（走官方 API），不做面板内真拖」。事实依据：**SketchUp issue #506** —— `UI::HtmlDialog` 发起 HTML5 拖拽时，**JS→Ruby 桥在 `onDragStart` 后冻结、直到松手才 flush**，拖动过程收不到任何回调 → 面板内真拖不可靠（此条同时修正 `docs/36 §3.1` 里「拖放可行性【待核实】」那一行的结论方向）。
2. **插件内解压 / 读压缩包** —— ID BOX 已负责解压落盘（含 GBK 处理，`docs/01 P0-2`）；插件只取用**已入库资产**。可搭鸭有 `seven_zip` + 自带 7z（`docs/37 §1`、`:60`）是因为它从云端下载包，与我们形态不同 → **不照搬**。
3. **加密分发** —— 可搭鸭 106/107 个 `.rb` 加密、AEAD 信封 + 自定义 Ruby IR（`docs/37 §0`、`§3.3`）；ID BOX 分发明文 asar，且这与本地工具定位冲突（`docs/37 §2` 明确不可照搬）。
4. **DPAPI + Ed25519 鉴权密封**（`DXAUTH2:`、`auth-cache-v2`，`docs/37:126`）—— 无云端账号；本地工具口径不变。③ 形态下**可以完全无 token**（靠文件目录权限），若走 ① 补充形态仍按 `docs/36 §4.3`「token + 默认关」。
5. **自删卸载路径**（SU<21 时 `File.delete(__FILE__)` + `rm_rf`，`docs/37:66`）—— 危险行为，不做。
6. **任何网络能力**：自升级（可搭鸭 `upgrade_plugin`）、预签名上传（`presigned_upload`，`docs/37 §2#7`）、使用统计（`model_use_analytics`）、联网诊断页 —— 全部不做。插件包内不应出现任何 http/socket 调用（可搭鸭逆向的实证是它原生层**无网络栈**，`docs/37:13`，这与我们的主动设计巧合一致）。
7. **参数化门窗 / 墙体 / CAD 生成 / Enscape 联动**（可搭鸭九组功能里的六组，`docs/37 §1`）—— 属它的商业主面，与 ID BOX「素材库」定位无关。V1.0 借的是它的**工程形态**，不是功能面（`docs/37 §0` 第 4 条）。
8. **跨进程写库 / 触发导入**（`docs/36` E4、§6 P4）—— 判重弹窗是进程内 UI，跨进程无解（`docs/36 §5.1 E4` 备注②），且"主进程读不到 Dexie"（`docs/25:2200-2201`）。
9. **多 DCC 支持** —— V1.0 只做 SketchUp（`docs/25:2212`「最容易，先做这个」）。
10. **UI 自动化** —— `docs/25:2195` 反向要求「不依赖 UI 自动化」。

## 4. ≤5 端点映射表（③ 为主形态下的落点）

> `docs/36 §5` 的 E1–E5 是按 ① HTTP 设计的。用户改主选 ③ 后，**三个端点降级为文件读取、两个不进 V1.0**。下表是逐项映射，不新增端点。

| `docs/36` 端点 | ③ 形态下的落点 | V1.0 |
| --- | --- | --- |
| **E1** `GET /health` | **`manifest.json`**（发现文件）：`apiVersion:"1"`、`appVersion`、`libraryRoot`、`generatedAt`、`pluginIndexEnabled`。读不到文件 = ID BOX 未启动/未开导出 | ✅ P0（P0-2） |
| **E2** `GET /assets`（**原文主线：搜词 → 绝对路径列表**，`docs/25:2207`） | **`index.json`** 资产快照 + 插件本地检索。字段：`id, name, kind, category1, category2, source, zhimoId, relFolder, mainFile, files[{rel,ext}], thumbRel, suMajor, generatedAt` —— **刻意不带 `tags/note/styles`**（J2，不暴露 schema）；① 补充形态时这些字段才在 HTTP 端点里出现 | ✅ P0（P0-3） |
| **E3** `GET /assets/{id}/path` | 并入 E2：插件每次从快照现取；插入前用 `manifest.libraryRoot` 现算绝对路径 + 存在性校验。**「不缓存路径」纪律不变**（`docs/16:100`、`docs/36 §5.3`）；快照与盘不符 → 提示"索引过期，请刷新"，等价于 `410 GONE` | ✅ P0（并入 P0-3/P0-5） |
| **E4** `POST /import` | ❌ 不进 V1.0（§3.3 第 8 条） |
| **E5** `GET /taxonomy` | P1：改为 `taxonomy.json` 只读快照（§3.2 P1-1） |

**V1.0 实际交付物 = 2 个文件（`manifest.json` + `index.json`）+ 一个 Ruby 面板。** 这是 ③ 相对 ① 的产品收益：**零服务、零端口、零 token，搜索即时**。代价是新鲜度 —— 见 §6.1 与 D1。

## 5. 用户 2026-11-04 的两条裁定（照此执行，不再讨论）

1. **「拖出」= 点一下即插入（走官方 API），不做面板内真拖。** 依据 SketchUp issue #506（HTML5 拖拽期间 JS→Ruby 桥冻结）。另记一条事实：从 Windows 资源管理器往 SU 视口拖文件本身可用，前提 SU 不以管理员运行（`README.md:196` 的系统级拖出同类）—— 用户既有工作流不受影响。
2. **协议主选 ③（已导出的索引 JSON，`file://` 清单 + 文件监视），① HTTP 作补充。** 用户原话里的「一个 JSON 文件」正是 `docs/36 Q8` 说的发现文件：两种形态都需要它，唯一要定的是**写到哪个固定路径**（插件不能猜）。

## 6. 从可搭鸭派生的功能（借工程形态，不借功能面）

| # | 它的做法（`docs/37`） | V1.0 采纳形态 | 复用 ID BOX 既有资产 |
|---|---|---|---|
| 1 | SHA256 指纹 + staging `.tmp-<pid>-<hex>` + `rename` 原子落盘（`docs/37:55`） | **索引 JSON 原子写**：先写 tmp 再 rename；插件读前比对 `manifest` 里的 `sha256`，避免读到半写文件 | 与 ID BOX 原子写/回滚同思路（`docs/36 §2.3`） |
| 2 | 按 Ruby 运行时分叉原生件目录（`native/{macos,windows}/`，2.7/3.2/3.4）（`docs/37:56`） | **V1.0 无原生件**，但把"版本对版本目录约定"写进插件包规范，将来需要时照此立目录 | —— |
| 3 | 错误码 `RVL-101..105` + loader 日志 + 用户可见诊断页（`docs/37:57`） | **错误码 + 结构化日志三件套**（§6.2） | ID BOX 已有日志面（诊断日志系统 + 崩溃现场捕获，TaskList #49 已落地） |
| 4 | 本地 HTML + `window.sketchup` 双向桥（`window.xxxInit/Change/Clear` ↔ `window.sketchup.xxx_data_change`）（`docs/37:58`） | **面板实现形态照此**：本地 HTML + `UI::HtmlDialog`，无网络无鉴权 | 与 ID BOX 的 IPC 形态同源但**跨进程不能直接用**（`docs/25:2201`），桥由插件自己实现 |
| 5 | 预置 skp + **属性字典驱动参数化组件**（`dx_jc_x` 门宽等 + `lock` 位）（`docs/37:59`） | 借用"字典键即参数字段、不新建 schema"这条形态 → 见 §7 的 `idbox_*` 字典 | 与 `Asset` 的可选字段先例同类（`types.ts:330`、`:403`） |
| 6 | 自带 7z 二进制 + rubyzip（`docs/37:60`） | ❌ 不采纳（§3.3 第 2 条）：插件不解压，只取用已入库资产 | 主进程解压管线 + GBK 已落地 |
| 7 | 预签名上传（`docs/37:61`） | ❌ 不采纳（J1 归属权一票否决 `docs/13:20`；供给侧不做 `docs/13:22`；云同步类已留档判否 `docs/13:138-146`） | —— |

**另有一条必须借的风险经验**：可搭鸭把文件搬到**纯 ASCII 缓存根**再 `load`，说明 **SketchUp 在 Windows 上加载非 ASCII 路径的本地扩展会出问题**（`docs/37 §3.2`）。我们的场景不同 —— 用户素材库路径**常态含中文**（插件读的是 JSON 里的数据路径，不是加载自身文件），所以：① 插件自身文件路径建议 ASCII；② JSON 一律 UTF-8，插件读时显式指定 UTF-8；③ 这条区别是【推断】，列入真机核实。

## 7. `idbox_*` 属性字典（来源回溯）

**形态借自可搭鸭（`docs/37 §2#5`），键名是我们自己的。** 属性字典机制本身有实证（可搭鸭用 `dx_jc_*` 键 + `lock` 位），Ruby API 的确切方法名（`set_attribute` / `attribute_dictionary`）**【待核实】** —— 核实方式：查 `ruby.sketchup.com/Sketchup/Entity.html` + 真机最小探针。**字典键是我们要定的契约，方法名不写死。**

设计原则：**工程文件里不写绝对路径**（路径非稳定契约，`docs/16:100`；改分类/改名/移库/rescan 都会让旧路径失效）→ 写 **UUID 主键 + 相对路径**，用时靠 `manifest.libraryRoot` 现算。

| 键 | 值 | 说明 |
| --- | --- | --- |
| `idbox_asset_id` | UUID | **唯一锚点**（`docs/01 P0-7` / `types.ts:294-295`：永不因改名/改库/改大类而变） |
| `idbox_rel` | posix 相对库根路径 | 换库后仍可解析（配合 `manifest`） |
| `idbox_name` | 显示名 | 沿用 `displayName()` 口径（`naming.ts:114`） |
| `idbox_kind` | `model\|texture\|cad\|hdri\|material` | 与 `AssetKind` 对齐 |
| `idbox_category1` / `idbox_category2` | 单段词表词 | **只读快照值**；插件不得写回、不得自造词条（词表纪律 `README.md:78`，真相源 `README.md:283`） |
| `idbox_source` | `知末网` / `3d66` / `手动导入` | 与 `Asset.source` 对齐（`types.ts:298-299`） |
| `idbox_zhimo_id` | 数字串 | 可空；有则便于回查详情页 |
| `idbox_inserted_at` | ISO8601 | 取用时间 |
| `idbox_api_version` | `"1"` | 兼容承诺：只增不删字段（`docs/36 Q10`） |

**隐私注意（J1）**：字典会随工程文件一起交付给第三方，因此**默认不写 `library_root`、不写工程文件路径**（可搭鸭把来源标记落库会记录用户工程路径，这是它的隐私面）。写字典的动作列 P1-5（跨进程写路径），V1.0 不在范围内。
