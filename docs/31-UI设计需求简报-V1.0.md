# ID BOX · V1.0 界面设计需求简报

> 这份文档**只描述事实与需求，不预设设计方案**。
> 视觉风格、信息架构、组件形态、密度取向，全部交给 UI 设计方自由发挥。
> 文档里出现的现有做法，是"现状描述"，不是"要求沿用"。

---

## 1. 这是什么软件

**ID BOX** —— Windows 桌面的**本地素材库管理器**（Electron 33 + React 18 + TypeScript + Tailwind 3 + Zustand + Dexie/IndexedDB）。

一句话：**把从知末网（znzmo.com）下载的模型 / 贴图 / HDR 压缩包拖进来，自动解压、剔除杂质、按分类落盘，然后变成一个能浏览、能预览、能拖回建模软件的本地库。**

- 完全本地离线运行，数据不出设备
- 素材库目录由用户自己指定（当前实测库规模约 1,284 项 / 12 GB 级别）
- 有浅色 / 深色两套主题
- 当前版本 v0.8.1（2909 条测试通过）

---

## 2. 用户是谁、怎么用

用户是**空间 / 主案设计师**，同时是独立开发者，工具链 SketchUp + AutoCAD 天正 + D5 Render，也用 PS / Figma。

典型场景：

1. **收素材**：在知末网批量下载，一次几十上百个压缩包，拖进软件就不管了
2. **找素材**：三个月后想找"那个中古风的壁灯""那张灰色大理石"，靠分类和眼睛扫
3. **比素材**：在几个候选材质之间反复看，确认纹理、比例、质感
4. **用素材**：把选中的 `.skp` 直接拖进 SketchUp / D5
5. **理素材**：事后补分类、打标签、标色、清理重复副本

## 3. 软件现在有哪些能力（设计需要承载的全部内容）

### 3.1 导入与归档
- 拖入压缩包（zip / 伪装成 rar 的 zip / 7z，含 GBK 编码修复）或单张图片
- 自动解压、**递归下钻**（压缩包里套一层目录也能找到真正的模型）
- 自动剔除杂质（站方二维码图、说明 HTML、说明文本、`__MACOSX`）
- 原包处置三选：保留原位 / 移入系统回收站 / 彻底删除
- 导入时遇到与库内重复的内容 → 弹窗让用户选择 **跳过 / 覆盖 / 两者都留并重命名**
- 导入完成后可撤销

### 3.2 分类
- 分类词表严格照抄知末网结构（一级 / 二级级联），不自创类目
- 导入时按文件名做预分类；未命中的落「未分类」
- 可从站方详情页抓回站方分类，一键重排，并可整体撤销
- 可选的 AI 兜底分类（用户自填 API，默认关闭）
- 资产可被指派 / 改分类，可拖到左栏分类节点归类（带撤销）

### 3.3 浏览与筛选
- 视图：网格（大 / 中 / 小三档密度）、列表、**双击进软件内文件视图**
- 多选：框选、Ctrl 点击、Shift 范围选、全选
- 筛选维度：**体积 / 导入时间 / 分辨率 / 色标 / 风格**，可叠加
- 排序：名称 / 导入时间 / 体积 / 分辨率 等
- 智能集合：把当前筛选条件存成一组，一键切回
- 搜索：名称 / 标签 / 分类
- 重复副本检测（同名但知末 ID 不同的不会被误判）

### 3.4 预览
- **材质球**：three.js 离屏渲染 PBR 材质球，可存成卡片封面
- **自定义渲染**：调反光 / 凹凸 / UV 重复 / 光线强弱，实时重渲，可「保存为封面」
- **HDR 预览**：`.hdr` 主进程降采样后可 0–360° 旋转，可拍照当封面
- 封面可手动更换（粘贴 / 拖图 / 选文件），可从知末重取

### 3.5 整理
- 重命名（单个 / 批量模板）
- 标签、色标、收藏、评分
- 别名（软件内显示中文别名，磁盘文件名不动）
- 回收站（软删 + 保留期 + 撤销），删除撤销期可设 不等待 / 3 秒 / 5 秒

### 3.6 接回工作流
- 卡片可**原生拖出**到 SketchUp / D5（拖的是那个 `.skp`）
- 文件视图里**每个文件可单独拖出**
- 打开所在文件夹

### 3.7 设置与诊断
- 设置分 7 个分页：外观 / 导入 / 分类 / 库 / 别名 / 数据与备份 / 关于
- 动效性能三档、主题、密度、撤销期、库目录、缓存、日志导出
- 检查更新、关于页（版本号、二维码反馈、GitHub Issue 入口）

## 4. 界面清单：每个界面要承载什么

> 下面只列"这个界面上有什么内容"，不规定它长什么样、放哪里。

### 4.1 全局骨架（当前状态，供参考）
- **顶栏**：Logo + 产品名、搜索、视图切换（网格/列表）、密度三档、设置、自绘窗口控制
- **左栏**：库导航（全部 / 分类树 / 收藏 / 重复 / 智能集合 / 最近删除）+ 导入入口 + 库路径 + 版本号
- **中栏**：视图标题 + 计数 + 筛选 + 排序 + 内容区
- **右栏**：选中资产的详情面板
- **底栏**：操作结果提示 + 撤销入口
- **浮层**：右键菜单、多选操作条、导入进度、拖入遮罩、各类弹窗

### 4.2 主界面 · 网格
要展示一张卡的哪些信息，由设计方决定。目前一条资产**可提供的字段**有：
封面图、名称、类型（模型 / 贴图 / 材质预设 / HDRI / 其他）、文件大小、文件数、
分辨率（2K / 4K …）、导入时间、来源、知末 ID、SU 版本、风格、标签、色标、
收藏状态、重复副本数、分类路径（大类 / 一级 / 二级）。

同时要支持：hover、选中、多选、拖出、拖到分类上归类、右键菜单、双击进文件视图。

### 4.3 主界面 · 列表
同样的数据，但用户在这里更多是"查"而不是"扫"。列什么、几列、怎么对齐，交给设计方。

### 4.4 文件视图（双击资产进入）
展示单个资产内部的文件列表（如 `_Color / _Normal / _Roughness / _AO / _Displacement`），
每个文件可单独拖出；顶部有材质球渲染区与调节控件；可返回。

### 4.5 详情面板
要承载：大预览（材质球 / 封面 / HDR）、更换封面、名称（可改名）、类型、来源与知末 ID、
导入时间、标签、收藏 / 评分 / 色标、重复副本、分类（一级 / 二级，材质类没有风格）、
备注、文件列表（按槽位分组）、打开所在文件夹、删除。
模型 / 材质 / HDRI 三类要显示的东西不一样（比如 HDRI 有「预览 HDR」按钮，模型有「从知末取封面」）。

### 4.6 自定义渲染面板
渲染画布 + 参数调节（反光、凹凸、UV 重复、光线强弱）+ 保存为封面。

### 4.7 HDR 预览
大画布 + 可旋转 + 加载进度 + 拍照当封面。

### 4.8 设置
7 个分页，内容见 3.7。当前弹窗尺寸 900×680，左导航右内容。

### 4.9 其他必须存在的界面
- 空态（库为空 / 筛选无结果 / 回收站为空 / 无重复）
- 加载态
- 导入进度与结果提示
- 导入重复处置弹窗（跳过 / 覆盖 / 都留）
- 删除确认 + 撤销条
- 右键菜单（卡片上 / 空白区，空白区要有「刷新」）
- 多选操作条
- 关于 / 反馈

## 5. 现在的问题（用户原话 + 实测数据，供诊断，不是方案）

用户原话（2026-10-27）：

> 「根据我们目前的功能深度优化 UI 排版，看看我们还能怎么把整个界面做得更加高效清爽，以及更加的专业。」
> 「一眼望过去，有些时候内容会特别特别多，特别是在主页的时候。」
> 「我想要有一个重构的感觉。」

实测到的现状（供参考，可推翻）：

| 现象 | 数字 |
|---|---|
| 左右两栏宽度 | 216 + 300 = 516px，占 1440 窗宽的 35.8%，**且都不可折叠**；右栏在没选中任何资产时也占着 300px |
| 中栏头元素数 | 12 个元素挤一行，横向余量仅约 7.8%；切换模型 / 材质 / HDRI 三类时同一排控件会横向跳动 |
| 单张卡片常驻信息 | 约 10 类（封面、类型徽标、数据通道徽标、色标、多选钮、收藏、重复数、归类抓手、标题两行、副行：类型·大小·文件数） |
| 卡片标题 | 恒占两行，第二行常年空着；元信息区 63px |
| 首屏可见卡片（1440×900，中密度） | 12 张 |
| 顶栏 | 高 56px，中段约 684px 是空白 |
| 底色层级 | 深色主题下描边只有一个色值，靠描边建立的层级信息基本丢失 |

## 6. 想要达成的目标

三个词：**高效、清爽、专业**。

- **高效**：找得到、少点击、一次能看更多候选（或看得更清楚——哪个更合理由设计方判断）
- **清爽**：主页不要一上来就糊一堆信息
- **专业**：像给设计师用的生产工具，不像示例程序

**不设验收数字**，判据由设计方自己提出并说明理由。

## 7. 硬约束（只有这些，没有风格约束）

- 平台：Windows 10/11，典型窗口 **1440×900**，最小 1080×680，自绘窗口控制（最小化 / 最大化 / 关闭，关闭钮红色）
- 技术栈：Electron 33 + React 18 + TypeScript strict + Tailwind 3 + Zustand + Dexie，ESM
- 测试环境是 vitest `node`，**没有 jsdom**，UI 只能靠源码守卫测试——设计时请考虑"哪些规则可以被写成纯逻辑断言"
- 必须支持浅色 / 深色两套主题
- 完全离线，不能依赖在线资源
- 用户明确拒绝过：花哨的玻璃拟态（backdrop-blur）、大范围渐变、橙色/棕色/紫色系高亮、系统原生下拉与复选框

除此之外**没有任何视觉风格限制**。之前版本用过的 Soft UI / macOS Vibrancy 只是历史选择，不是约束，设计方可以完全推翻。

## 8. 需要设计方回答的问题

1. 主页的信息架构应该是什么：几栏、各栏承担什么、哪些信息常驻 / 按需出现？
2. 一张卡片该显示几项信息？为什么是这几项？其余信息去哪里找？
3. 「扫」和「查」是不是应该分成两种视图（比如网格 vs 列表）分别承担？
4. 详情面板应该是常驻栏、抽屉、还是别的形态？理由是什么？
5. 筛选、排序、视图这些控制项应该放在哪里？怎么避免切换视图时控件横跳？
6. 密度取向：更倾向"一屏更多、卡片更小"还是"一屏更少、卡片更大"？
7. 有没有我们没想到、但专业素材库软件该有的界面元素或交互？
8. 如果要分阶段落地，第一刀应该切哪里？
