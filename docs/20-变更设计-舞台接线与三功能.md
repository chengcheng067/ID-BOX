## 3. B · 虚拟滚动

### 3.1 裁定：**自研固定行高窗口化，不引 `@tanstack/react-virtual`**

**理由**（按重要性排序）：
1. **没有它要解决的问题**：外部库 80% 的价值在"未知/动态行高测量"。我们的行高由 `gridDensity` 完全确定（卡片固定宽高比 + 元信息定高），是**纯固定行高**场景，动态测量的复杂度用不上。
2. **必须深度定制**：源卡 pin（§6）、Shift 区间按**逻辑索引**（不是 DOM 顺序）、拖拽/右键锚定、`dupOnly` 分组视图的组头跨行——这些在外部库里仍要写适配层，净代码量相当，但多了一个依赖与升级面。
3. **离线安装与包体纪律**：本项目一贯"不为一个函数引一个包"。自研核心是一个纯函数 `computeWindow()`（约 60 行）+ 一个 hook（约 80 行），可 100% 单测。

### 3.2 结构

```ts
// src/renderer/logic/virtualGrid.ts（新增，纯函数）
export interface WindowInput { scrollTop: number; viewportH: number; columns: number; rowH: number; rowCount: number; overscanRows?: number; pinnedRows?: ReadonlySet<number> }
export interface WindowOutput { startRow: number; endRow: number; padTop: number; padBottom: number; rows: number[] }
export function computeWindow(i: WindowInput): WindowOutput
```
- 高度用 `padTop/padBottom` 两个 spacer 撑（**不用 absolute 定位**——absolute 会让 `auto-fill` 列宽计算失效，且 `gap-card` 语义要手写）。
- `columns` 由容器宽度算：`max(1, floor((W + GAP) / (MIN_W + GAP)))`，`GAP=14`、`MIN_W` = 240/184/132（与 `GRID_COLS` 同源常量，**抽成共享常量避免两处漂移**）。
- `rowH` = `colWidth*0.75 + metaH`（meta 行高按档位固定），**每档一个常量**，T-01 落地时用 `getBoundingClientRect` 校一次。
- **网格与列表共用一套**：列表 = `columns:1, rowH:44`（现有行高），同一个 hook、同一个 `computeWindow`。
- `gridDensity` 变更 → columns/rowH 变化 → `scrollTop` 归零（否则位置错乱），并在 hook 内一次性 `ResizeObserver` 重算。

### 3.3 回收后如何保住交互语义

| 能力 | 保住方式 |
| --- | --- |
| 单选/多选 | 选择集是 `Set<id>`，与 DOM 无关；卡片只是投影 |
| Shift 范围选 | 用 `visibleOrderRef`（**全量逻辑顺序**，现有实现已有）算区间，再映射回 id —— 回收不影响 |
| Ctrl+A | 取 `visibleOrder`，不取 DOM |
| 拖出 | `draggable` 挂在卡片上；**拖拽期间 pin 源卡**（§6），dragend 释放 |
| 右键菜单 | 菜单锚点用 `{x,y}` 快照 + `contextMenuId` pin，菜单关闭释放 |
| 滚动位置 | 只在 density/筛选/排序变化时归零；普通滚动保留 |
| 焦点/键盘 | 仅保留 `Ctrl+F` 聚焦搜索（现有），**不做**卡片键盘导航（见 §10） |

## 4. C · 最近删除

### 4.1 裁定：**库内 `.trash/` 软删除 + 最终落到系统回收站**（不是二选一）

**三步链路**：`删除 → rename 到 <库根>/.trash/<assetId>/ （同盘 O(1)）→ Dexie 标 deletedAt` → 30 天/超容量/手动清空时 `shell.trashItem` 进系统回收站。

**为什么不只保留系统回收站**：应用内无法枚举/还原系统回收站（跨平台 API 不存在），"最近删除"页面就无从做起。
**为什么不彻底改成库内删除**：`shell.trashItem` 是"手滑了也能从 Windows 回收站捞回来"的最后一道网，砍掉它等于降低安全等级。
**为什么不做"复制一份到 .trash"**：GB 级资产复制 = 双倍磁盘与 IO，不可接受；`rename` 同盘是 O(1)。

### 4.2 语义变化（**必须向用户讲清**）

| 维度 | 现在 | 变更后 | 用户感知 |
| --- | --- | --- | --- |
| 删除瞬间 | 文件进 **Windows 回收站** | 文件移到 `<库根>/.trash/<assetId>/`，**仍在库盘上、占空间** | 资源管理器里原位置消失；磁盘占用**没减少**（直到清空） |
| 撤销窗口 | 5 秒（过期即不可恢复） | **30 天**，且「最近删除」页可随时还原 | 敢删了；但会疑惑"为什么空间没释放" |
| 彻底删除 | 5 秒后自动 | 手动「清空」或超过 30 天/容量上限 → 才进系统回收站 | 清空后仍可从 Windows 回收站捞回（双保险） |
| 原包处置 | 3 档不变 | **不变**（导入时清原包仍走 `trashOne`，不进 `.trash`） | 无变化 |

> **结论：这是一次真实语义变更，必须在「最近删除」页顶部与设置页各写一行说明："删除的资产先移到库内回收区，清空后才进入 Windows 回收站。"** 不做静默变更。

### 4.3 规格

| 项 | 裁定 |
| --- | --- |
| 字段 | `Asset.deletedAt?: number`（Dexie 索引）、`Asset.trashRel?: string`（`.trash/<id>` 相对路径，便于还原） |
| 默认过滤 | 集中一处：`applyFilters` 入口先 `assets.filter(a => !a.deletedAt)`（**禁止在每个消费点各写一遍**） |
| 保留策略 | **30 天** + **容量上限 5 GB**（先到者先清）；启动时 + 每日首次唤醒各跑一次 `purgeTrash()`（用 `settings.lastTrashPurgeAt` 去重，不引定时器） |
| 还原路径冲突 | 目标已存在 → `uniqueName(base, taken)` 追加 `-2` 并**在还原 toast 里明说**（不静默）；原 `<大类>/<一级>/<二级>` 目录不存在 → `mkdir -p` 重建（磁盘是真相，不查词表） |
| rescan | **硬约束：跳过 `.trash`**（`rescan.ts` 的四层解析入口加排除），否则软删资产会被重新索引出来 |
| 舞台 | 舞台打开中删除该资产 → 先 `closeFolderView()` 再收口；`stageOrigin` 快照失效则直接 idle（不播动画） |
| 详情面板 | 软删资产不可选中；若通过「最近删除」页打开，按钮变「还原 / 彻底删除」，拖出禁用 |
| 拖出 | 软删资产 `beginSystemDrag` 前置守卫拒绝（文件已不在原路径） |
| 清空 | 逐个 `trashOne`（沿用现有 `trash.ts` 双策略），成功后删 Dexie 记录 + `deleteThumbs(id)` |
| IPC | 新增 `trash:softDelete` / `trash:restore` / `trash:list` / `trash:purge`（`ipc.ts` + `preload` + `main/index.ts` 三处同步） |

## 5. D · 别名映射

### 5.1 裁定：**独立 `aliases` 词典表 + `Asset.aliasOverride?` 单资产覆盖**（不是纯 Asset 字段）

| 方案 | 判定 |
| --- | --- |
| 只加 `Asset.alias` | ❌ 否决：同一英文名（如 `Polished_Concrete`）在库里 50 个资产，要改 50 次；Crystal 包恰恰是"同名多份"的重灾区 |
| 只加独立表 | ❌ 否决：少数资产需要例外（同一英文名不同用途），没有覆盖位就只能改文件名——违反"不改文件" |
| ✅ **词典表 + 单资产覆盖** | 改一条词典 = 全库同名资产同步；个别例外用 `aliasOverride` |

```ts
// Dexie v5 新表（与 C 的 deletedAt 同一次迁移，见 §7）
export interface AliasEntry { key: string; alias: string; source: 'manual' | 'suggested'; updatedAt: number }
// key = normalizeAliasKey(asset.name)：小写、去扩展名、去尾部 _4K/2K/8K/1K、_ - 空格归一
```

### 5.2 影响面（主理人要求"只影响显示与搜索"——逐项钉死）

| 维度 | 是否受影响 | 说明 |
| --- | --- | --- |
| 落盘 `name` / `relFolder` / `folder` | **否** | 磁盘文件名一个字母都不改（用户原话的硬约束） |
| `dedupeKey` | **否** | 去重仍按真实名，否则"同一包的两份"会被别名伪装成不同资产 |
| 搜索 | **是** | `searchHaystack(a, alias?)` 追加别名；**中英文都能命中**（原名与别名都在 haystack 里） |
| 排序（按名称） | **是**（归入显示层） | 用 `displayName` 排序，否则中文用户按拼音找不到预期位置；`sortAssets(list, sort, displayNameOf?)` 可选参数，默认用 `name` |
| `kind` / `category1/2` / `styles` | **否** | 别名是"名字的中文投影"，不参与分类判定 |
| 缩略图 / 封面 / 舞台 | **否** | 与名字无关 |

**显示解析**：`displayName(a) = a.aliasOverride ?? aliases.get(normalizeAliasKey(a.name)) ?? a.name`（纯函数，放 `logic/alias.ts`，可测）。

### 5.3 交互与建议

- **编辑入口**：① 详情面板标题旁「别名」铅笔（单资产 → 写 `aliasOverride`）② 设置·整理 →「别名词典」列表（增删改一条 = 影响 N 个资产，保存前显示"将影响 12 个同名资产"）③ 「最近删除」无关。
- **自动建议**：复用 `autoClassify` 词表 + AmbientCG/Crystal 命名词典（`docs/` 里已有材质词），把英文 token 映射成候选中文；**只给建议、绝不自动写入**（材料名是用户资产，写错比不写更糟）。
- **批量套用**：编辑词典项时提示影响数量；改名后无需 rescan（只是显示层）。
- **重名多资产**：词典一条覆盖全部；单资产例外用 `aliasOverride`（详情面板编辑的就是它）。

## 6. 硬冲突：虚拟滚动 × 舞台（必须给机制）

**冲突**：虚拟化会回收卡片 DOM，而舞台动画依赖"被点中那张卡"的 `rect` 与节点；动画中途被回收 → 拿到 null rect 或飞到错误位置。

**裁定：三层防护，缺一不可。**

1. **rect 快照优先（根本解）**：`dblclick` 同步读取 `event.currentTarget.getBoundingClientRect()` → 存 `stageOrigin`（易失，不进 Dexie）→ **动画全程只读快照，绝不再读 DOM**。即使卡片立刻被回收，飞行轨迹也正确。
2. **源卡 pin 不回收（保证卡片淡出这一段有对象）**：P0/P1 期间源卡必须留在 DOM（要给它加 `data-stage-source` 做 `opacity→0`）。
   - **pin 实现点 = 虚拟窗口计算层**，不是卡片层：`useVirtualWindow({ ..., pinnedIds })` 内部把"含 pinned id 的行"并入可见行集合。放在卡片层会导致每张卡都订阅 pin 状态（2000 次订阅），这是性能倒退。
   - **pin 生命周期**：`dblclick` 起 pin → `phase==='active'` 释放（此时卡片已透明且网格已隐去）；`draggingId` 从 dragstart 到 dragend；`contextMenuId` 菜单打开期间。
3. **快照兜底**：`stageOrigin` 缺失或 `width/height === 0` → **无飞行、直接淡入顶栏目标位**（不崩、不飞到左上角）。

**附加约束**：opening/closing 期间 scrim 用**非 passive** `wheel` 监听 `preventDefault()`，锁住网格滚动——否则源卡可能滚出视口，第 2 层 pin 就白做了。

## 10. 不做清单

1. **不做动态行高**（卡片高固定）；不做瀑布流/不等高布局。
2. **不做卡片键盘导航**（↑↓←→ / 空格选中）——现有产品没有，虚拟化后再加成本翻倍，留 v2。
3. **不做"最近删除"的多选批量还原**（v1 只支持单条 + 全清空）。
4. **不做别名自动写入**（只建议）；不做机器翻译 API（离线优先，且材质术语机翻质量不可控）。
5. **不做别名影响 `dedupeKey`/落盘**（用户明确"不改变文件本身名字"）。
6. **不引入 `@tanstack/react-virtual`**（理由见 §3.1）。
7. **不做系统回收站的反向枚举**（跨平台无 API，能力上做不到）。
8. **不改原包处置三档**（备份/删除/保留原包语义与 `.trash` 无关）。
