## 2. 资产流转（产品的主干流程）

```
拖入压缩包（或点导入）
   │
   ▼
① 磁盘空间预检 ──不足──▶ 拒绝 + 提示可用/需要（不建任何目录）
   │足够
   ▼
② 解压（7z 优先，GBK 乱码自动嗅探重试）→ 落 staging（同盘，可 O(1) rename）
   │
   ▼
③ 剔除杂质：微信扫码 / 推广 html / 说明 txt / 经典垃圾名 ──▶ 不进文件列表、不当封面、不计体积
   │
   ▼
④ 定 contentRoot：剔除后顶层只剩 1 个文件夹 ──▶ 取其内部为内容根，资产名=文件夹名
   │                                    （例：中古侘寂屏风_木屏风_藤编屏风_可折叠）
   ▼
⑤ 定大类（由文件内容决定：skp→模型、jpg→贴图……）→ 落盘
   库根/<大类>/未分类/未分类/<资产名>        ← 导入零打断，分类事后指派
   │
   ▼
⑥ 缩略图生成（nativeImage 缩到 ≤480px，vault://thumb/ 提供）
   │
   ▼
⑦ 原压缩包 → 移入回收站（默认）/ 彻底删除 / 保留（三档可设）
   │
   ▼
⑧ 浏览 → 指派分类（详情面板/右键/多选批量）→ 拖出到 SU·D5 / 双击 reveal 主模型
   │
   ▼
⑨ 删除：二次确认 → 5 秒撤销期（文件仍在磁盘）→ 到期回收站 + 删索引 + 清缩略图
```

## 4. 缩略图策略（✅ 已拍板，2026-10-13 用户杨雯丞）

**决策**：
1. **提取 SKP 内嵌预览图**（首选）——.skp 文件头含 SU 保存时写入的预览图，大多数知末包其实有
2. **SU 图标兜底**——没有内嵌预览时，用 SketchUp 的模型文件图标做占位
3. **预留用户自定义入口**——用户可自行打开模型截图，直接**粘贴/拖入**软件，保存为该资产的预览图

> 用户原话：「我觉得可以先看一下 Su 有没有生成软件的预览图，如果没有的话，就先用 Su 图标兜底。我觉得可以提取一下 SKP 内嵌的预览图，然后预留接口，让用户截图以后直接扔进软件，就能贴在这个 Su 预览图片上。」

**封面优先级**（工程实现按此排序）：`skp 内嵌预览` > `包内预览图（现有四级回退）` > `SU 图标占位（UI 层）` > `用户粘贴的图片`（用户设置后永久覆盖，`coverSource='manual'`）

## 5. 材质浏览器（M6，你报“做丢了”）

**形态已拍板（2026-10-13 用户杨雯丞）**：**网格缩略图 + 详情区材质球**。
原因（调研实测约束）：Chromium 同时只能开 8-16 个 WebGL 上下文，网格里铺几十个材质球会崩——所以材质球只能“选中哪个渲染哪个”。网格用包内 `Preview.png` 当缩略图（与模型一致），悬停/选中时右栏详情区实时渲染球（three.js，已拍板）。

**用户样本已到并核实**（Crystal/AmbientCG 标准包 `Brick_Rough_vh1sbjl_2K_surface_ms.zip`，8 项扁平无嵌套）：
```
vh1sbjl_2K_Albedo.jpg / _AO.jpg / _Normal.jpg / _Roughness.jpg / _Displacement.jpg / _Displacement.exr
vh1sbjl_2K.json                    ← 42KB 元数据（AmbientCG 格式）
Brick_Rough_vh1sbjl_surface_Preview.png   ← 预览图，封面用它
```

**材质球槽位映射**（样本证实命名规范就是 PBR 标准名）：`Albedo→基础色`、`Normal→法线`、`Roughness→粗糙度`、`AO→环境光遮蔽`、`Displacement→置换`。

**⚠️ 重大发现：包内 `.json` 是权威名称源**——实测其内容为结构化语义标签：
```json
"semanticTags": { "name": "Square Floor Tiles", "contains": ["tiles","grout","dirt"],
  "theme": ["walkways","pavements","floors"], "descriptive": ["old","worn","red","square"],
  "color": ["Red","Brown"], "country": "United States" }
```
**这改变了“英文名中文显示”的做法**：不需要硬猜文件名——**优先解析 json 拿正式名 + 语义标签（可翻译），文件名只当兜底**。`Square Floor Tiles → 方形地砖` 是基于语义的翻译，比逐词硬译稳得多。

仍待你补：更多 Crystal 材质包样本（校准槽位识别的边界情况，如不同站点命名差异）。

## 6. 视觉方向（给 UI Agent 的输入，先记着）

你说“现在呈现的质感不是一个成熟的设计软件的质感”。参考你一贯的审美判据（安静的自然系高级感：暖木 + 克制 + 层次，靠阴影不靠玻璃），我建议 UI Agent 的 brief 里写死：
- **禁**：玻璃拟态/backdrop-blur、渐变滥用、高饱和点缀色、圆角过大的“玩具感”
- **要**：中性暖灰底 + 单一强调色、紧凑信息密度、真实阴影分层、SU 徽标这类小信息用 chip 而非色块
- 参照物：Blender 的资产浏览器、D5 的资源库、PureRef 的冷静感——而不是“国产工具风”
