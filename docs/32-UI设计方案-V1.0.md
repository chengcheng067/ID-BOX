# ID BOX · V1.0 界面设计方案

> 输入：`docs/31-UI设计需求简报-V1.0.md`。本文只做设计判断，不改动产品代码。
> 诊断过程中另核对了 `src/renderer/styles.css` 的主题 token 与 `logic/gridMetrics.ts` 的度量常量，作为下判断的依据。

---

## 0. 一句话主张

**把界面从「信息陈列柜」改成「一块画布 + 两套按需浮现的上下文」——封面当主角，控件退到后台，细节随选择而来。**

方向名：**中性工具面（Neutral Instrument Panel）**。参考系是 Bridge / Capture One / Eagle 那类生产力工具的克制感，不是消费级应用的装饰感。推翻 Soft UI 与 macOS Vibrancy。

---

## 1. 诊断：问题的根不是"挤"，是"平权"

简报里的数字是线索，结论如下。

**1.1 一切信息同权重、同常驻。**
一条资产有 16 个字段，卡片常驻 10 类；中栏头 12 个控件挤一行；左右两栏永久占 516px。三者是同一个病：**没有优先级**。当所有东西都"一直可见"，界面就失去了"此刻该看什么"的能力，用户只能自己过滤——这就是"一眼望过去内容特别多"的真正来源。不是数量问题，是**信噪比没有分层**。

**1.2 右栏在为「不存在的对象」预留空间。**
未选中任何资产时详情面板仍占 300px。这是结构性的浪费：界面的主区被一个空容器削掉 20%。真正的代价不在 300px，而在它让"内容区"这个概念变得不确定——用户永远看不到全宽画布。

**1.3 控件横跳的根因不是宽度不够，是控件集合在变。**
横向余量只剩 7.8% 只是表象。真正的机制是：切换模型 / 材质 / HDRI 时，**控件本身增删**了。只要控件集合随数据形态变化，再宽的栏也会跳。修宽度是治标，修"集合稳定性"才是治本。

**1.4 卡片在同时扮演两个角色。**
它既是缩略图（服务于"扫"）又是数据行（服务于"查"）。两个角色的最佳密度是相反的，合并的结果是哪边都不达标：扫的时候被副行干扰，查的时候列宽不够。

**1.5 深色的层级是单通道的，所以必然失效。**（实测证据）`styles.css` 里 `--border / --border-panel / --border-soft` 在浅色下是三个不同值（`#e2e8f0 / #e8edf2 / #eef1f4`），在深色下**塌缩成同一个值 `#2a2a2d`**；同时 `--shadow-card` 深色下为 `none`，卡片底 `#1c1c1e` 与画布底 `#111113` 亮度差极小。结论：**深色下"描边 + 投影"两条通道同时失效，只剩一条极弱底色差撑着**。这不是配色没调好，是层级体系只有单一通道，一断就全断。

**1.6 两个历史遗留的"不像 Windows"。** ① `--accent: #007aff` 是 **Apple 系统蓝**，Windows 原生强调色是 `#0078D4` 系——这是"像示例程序、不像生产工具"的隐性来源，多数用户说不出但能感觉到。② `--preview: #7a5af8`（深 `#b18cff`）是**紫色高亮**，落在简报 §7 明确拒绝过的色系里。

**1.7 为了对齐牺牲了信息。** 标题恒定两行（`CARD_META_H = 63`），第二行常年空着。虚拟滚动里对齐确实重要，但用"补一行空白"来对齐是错的解法，正解是**固定行高容器 + 单行 clamp**。

> **总诊断**：这是一个"所有东西都同时可见"的界面。高效界面的本质不是"放得下"，而是**在正确的时刻显示正确的东西**。

## 2. 信息架构：2 栏常驻 + 第 3 栏按需

| 栏 | 状态 | 承担 | 宽度 |
|---|---|---|---|
| 顶栏 | 常驻 | 品牌、搜索、设置、窗口控制 | 44px 高 |
| 左栏 | 常驻，**可折叠** | 「我在哪」：库导航、分类树、集合、导入入口 | 216 ↔ 48，状态记忆 |
| 中栏 | 常驻 | 「有什么」：唯一主角 | 弹性，吃掉右栏的 300px |
| 右栏 | **按需**（抽屉/可钉住） | 「这一条是什么」 | 0 / 320（覆盖）/ 320（挤压，仅钉住时） |
| 底栏 | 按需浮出 | 操作结果 + 撤销 | 有内容才出现 |

**取舍理由**：左栏常驻是因为"切换分类"是高频主动操作，收起它每次都要多一次点击；右栏按需是因为"看详情"是低频且**被动**的——它由"选中"触发，没有选中就不该存在。这是唯一有争议但值得拍板的取舍（见 §13-Q4）。

### 分层规则（这套规则本身是可测的）

| 层 | 出现条件 | 内容 |
|---|---|---|
| L0 常驻 | 永远 | 导航树、搜索、视图/密度、导入入口 |
| L1 静态 | 有则显示 | 卡片封面、名称、选中态、色标 |
| L2 浮现 | hover / 选中 | 类型、体积、分辨率、文件数、时间；卡上 2 个快捷动作 |
| L3 深层 | 详情 / 列表 / 文件视图 | 来源、知末 ID、SU 版本、标签、备注、重复副本、分类路径 |
| L4 情境 | 触发才出现 | 底栏、条件行、多选条、导入进度、抽屉 |

**粒度控制**：架构只规定"栏的存续规则"与"字段属于哪一层"，不规定像素。字段层归属写成一份**配置数据**（`FIELD_LAYER: Record<FieldName, 0|1|2|3|4>`），而不是散在 JSX——这样在没有 jsdom 的 vitest 环境里可以直接断言"卡片渲染的字段集合 ⊆ L1∪L2"。这是本方案对测试约束的直接回应。

## 3. 卡片：常驻 3 项

**封面 + 名称 + 1 个状态指示（色标优先）**。其余全部下沉。
- **封面**：决策主依据，占卡片面积 ≥ 70%。素材库里"看图"就是决策本身。
- **名称**：唯一无歧义标识，中文别名优先，单行 clamp（不再恒两行）。
- **状态指示**：选**色标**而非类型徽标。色标是用户自己打的、携带语义、无法从封面推断；类型在左栏已按大类导航的上下文中基本冗余（在"贴图"分类下每张卡都写"贴图"是纯噪声）。这是"**上下文已提供的信息，卡片不再重复**"的第一处应用。
- **hover** 才浮出一行「分辨率 · 体积 · 文件数」与右上角两个动作（收藏 / 拖出）。
- **类型**降为封面右下角 11px 字形标识（非徽标块），大类上下文明确时可完全省略。
- **其余**：详情面板（L3）。

**代价**：不 hover 就看不到体积/分辨率，键盘/触屏用户吃亏。缓解：列表视图承担"查"，查档承担"看全字段"。

## 4. 详情面板：按需抽屉，可钉住

**选：默认 overlay 抽屉（从右推入，宽 320，覆盖内容区）；提供「钉住」转为常驻挤压栏，状态记忆。**

- 为什么不是常驻栏：0 选中时白占 300px（诊断 1.2），且它让内容区宽度永远不确定。
- 为什么不是纯抽屉：真实场景「比素材」需要**同时**看大图和其余候选（简报 §2 场景 3）。纯抽屉做不到对照。
- 所以是**三态**：无 → 抽屉（覆盖，不挤压）→ 钉住栏（挤压）。默认抽屉，钉住是用户主动升级。

**另立一条快路径：Quick Look（空格）**——全屏暗底浮层，纯预览无编辑，←/→ 切换上一张/下一张，Esc 退出。「比素材」的主路径应该是 Quick Look，详情面板只管"编辑与补全"，两者职责分开。**这是本方案最重要的新增交互。**

**代价**：抽屉挡住内容区右侧约 22%。缓解：抽屉可被 Esc / 取消选中关闭；需要长期对照时钉住（此时用户已明确接受挤压）。

## 5. 控制面：固定槽位 + 条件行

中栏头拆成两行，不再挤一行。

```
第 1 行（上下文行，常驻）   贴图 · 大理石   1,284 项        [视图][密度][排序][筛选]
                            左对齐固定        ←弹性区→        右对齐固定，顺序恒定
第 2 行（条件行，按需）     [4K ×] [灰色 ×] [本月导入 ×]        清空全部
                            无筛选时这一行不渲染，不留白
```

**避免横跳的四条具体手段**（这是本节的核心判断）：

1. **槽位固定**：视图 / 密度 / 排序 / 筛选四个入口的位置与顺序**永不改变**，只改内部状态。
2. **维度不可用 → 置灰，不删除**。切到 HDRI 时"分辨率"筛选项留在原位并置灰 + tooltip 说明，而不是从布局里消失。**消失 = 重排；置灰 = 位置恒定**。这一条是横跳问题的根治手段。
3. **筛选收进 popover**，不横向展开。所有维度在浮层内，中栏头横向宽度恒定。
4. **弹性区吸收变化**：标题左对齐、控件组右对齐，中间空白承担所有宽度波动。

**「当前视图」必须永远可读**：激活的筛选以 chip 形式列在条件行，可单删、可一键清空、可一键存为智能集合。用户三个月后回来最大的障碍不是筛不到，是**忘了自己筛过什么**。

## 6. 密度取向：更多、更小——但"看清"另开专路

**选「一屏更多、卡片更小」。**

理由不是"更多更好看"，而是素材浏览的本质是**排除法**：用户不是逐张欣赏，是快速排除不合格项。排除速度 ≈ 同屏候选数。1,284 项在 12 张/屏下要滚 107 屏，这不是"不够爽"，是**任务不可完成**。

而"看得清楚"是另一种任务，不该由网格承担——它由 hover 大预览 / Quick Look / 详情面板承担。职责分离之后，网格就可以放心变密。**这是本方案的关键取舍：用「专路」换「密度」。**

具体标定：

| 档 | minmax | 意图 | 副信息 |
|---|---|---|---|
| 扫（默认） | **152** | 快速排除 | 名称单行，无副行 |
| 看 | **200** | 检视确认 | 名称 + 一行「分辨率·体积」 |
| 查 | 240（保留） | 全字段核对 | 全部副信息 |

- 元信息区 63px → **40px**（固定高度容器 + 单行 clamp，保留虚拟滚动的基线稳定）。
- 目标首屏（1440×900，扫档）：**24–30 张**（当前 12）。
- 硬边界：**密度提高靠"减文字、缩间距"，不靠"缩封面"**。最小卡宽 112 时封面有效像素仍 ≥ 96×96——对材质缩略图判断纹理与色相足够。
- 三档的命名从「小/中/大」改为「**扫 / 看 / 查**」，让档位直接对应意图，而不是对应尺寸。

## 7. 视觉方向

### 7.1 色彩观感
**素材本身是彩色的，所以界面必须是无色的。** 这是素材库软件的第一原则——UI 不能与内容的颜色竞争。低饱和中性灰阶为骨，强调色**只保留一个**，且**只用于状态（选中 / 激活 / 进行中），不用于装饰**。语义色（删除红 / 成功绿）只用**文字与图标色**，不用大面积底色。

### 7.2 层级手段：双通道冗余（回答诊断 1.5）
- **主通道 = 底色分层**，四级：`canvas → sidebar → card → elevated`，相邻两级亮度差 ΔL ≈ 3–5。
- **副通道 = 1px 描边，必须有至少两档**：hairline（分隔）/ strong（容器轮廓）。深色下 hairline `rgba(255,255,255,.07)`、strong `rgba(255,255,255,.16)`——**不再是同一个值**。
- **投影只用于浮层**（弹窗 / 抽屉 / 多选条 / 右键菜单）。**卡片不用投影**：深色下它几乎不可见，却在 1,284 项虚拟列表里产生真实的绘制开销。卡片与画布的区分交给「底色差 + hairline」。
- **留白优先于分隔线**做分组。

### 7.3 关键色值（方向性举例，双主题对照）

| 角色 | 浅色 | 深色 |
|---|---|---|
| canvas（中栏底） | `#F7F8F9` | `#0F0F11` |
| sidebar（侧栏/底栏/抽屉） | `#F1F2F4` | `#161619` |
| card | `#FFFFFF` | `#1B1B1E` |
| elevated（输入框/操作条） | `#FFFFFF` + hairline | `#232327` |
| 描边 hairline / strong | `#E6E8EB` / `#D3D7DD` | `rgba(255,255,255,.07)` / `rgba(255,255,255,.16)` |
| 正文 / 次要 / 弱化 | `#1F2328` / `#57606A` / `#8C959F` | `#F2F2F4` / `#9CA3AF` / `#6B7280` |

**强调色换成 Windows 原生蓝**（替换现状的 Apple `#007aff`）：浅 `#0A6CDA` / 深 `#5AA9FF`；危险色：浅 `#D13438` / 深 `#FF6B6B`。
**紫色 `--preview` 撤掉**，改中性色或并入强调色通道（它落在用户明确拒绝的色系里）。

### 7.4 字号 / 圆角 / 间距
- **字号只有三级**：`13px` 正文与控件、`12px` 卡片标题与表格、`11px` 计数与徽标（下限，不再更小）。层级靠**字重 400/500/600 + 颜色三级**，不靠更多字号。中文字体走系统 UI（微软雅黑 UI），行高正文 1.5 / 标题 1.25。
- **圆角偏小 = 精密感**：卡片 / 输入框 / 弹窗 `6px`，按钮 / chip / 徽标 `4px`。8px 以上会显软，与"生产工具"的目标相悖。
- **间距走 4 的栅格**：卡间距 14 → `12`，列表行高 44 → `40`。
- **水平间距 < 垂直间距**：信息行内紧凑、信息块间宽松。这是让密集界面透气的低成本手段。

## 9. 我们没想到、但专业素材库该有的

按价值排序，前三条我最想推。

1. **Quick Look（空格）**——见 §4。当前"比素材"只能双击进文件视图，太重。
2. **对比模式（Compare）**——专业素材库的标志性能力。多选 2–4 张并排，同缩放、同步 pan/zoom、同一组参数。**材质选型是比出来的，不是单看出来的**，而当前完全没有。
3. **「当前视图」永远可读 + 可存**——见 §5。不是新功能，是把已有状态变成可见。
4. **最近使用**——"拖出过"哪些是最强召回线索。「三个月后找那个壁灯」更可能是"我上次用过"，而非重新筛。记 `lastUsedAt`，左栏加「最近使用」、排序加一项。低成本高价值。
5. **按主色筛选**——封面提取主色建色相/明度桶（离线可做）。用户回想的方式是"那张**灰色**大理石"，色相比标签更贴合设计师记忆结构。
6. **整理流水线**——进「未分类」→ 单张全屏 + 底部一键分类 + **自动跳下一张**。把"理素材"从 O(n) 次点击降到 O(n) 次按键。1,284 项里的未分类就靠这个清掉。
7. **键盘效率**：空格=Quick Look、F2=重命名、Ctrl+1..5=色标、Ctrl+D=收藏、方向键导航；打完色标自动跳下一张（Lightroom 的 Advance）。
8. **渐进式封面加载**：主色色块 → 缩略图 → 全图。1,284 项滚动时这一条决定"跟不跟手"。
9. **库漂移的轻量指示**：`libraryDrift` 已有逻辑但界面无位置——文件缺失 / 目录变更要在卡片与左栏上有安静标记。专业工具的可靠性体现在这里。
10. **备注可被搜索**——三个月后的回忆常常是"我当时写了什么"。

**反向建议（明确不做）**：不做仪表盘 / 统计页，不做标签云，不做常驻 AI 推荐入口。素材库只有"找素材"一个核心任务，任何稀释它的东西都不该进 V1.0。

## 11. 落地顺序：第一刀切空间，不切视觉

判断依据：用户说"内容特别多"，这首先来自**空间分配与信息权重**；只翻新视觉不改变拥挤感，是典型的高投入低感知。

| 阶段 | 内容 | 交付判据 |
|---|---|---|
| **P0 空间重构**（第一刀，风险最低、不碰业务逻辑） | ① 右栏改抽屉 + 可钉住 ② 左栏可折叠（216↔48，记忆）③ 卡片字段削到 3 项、元信息 63→40、标题单行 ④ 密度重标定 152/200/240 | 判据 1、2、4、5 |
| **P1 控制面稳定** | ⑤ 中栏头两行化、槽位固定 ⑥ 筛选 popover + 条件 chips 行 ⑦ 维度置灰而非移除 | 判据 3 |
| **P2 视觉系统** | ⑧ 四级底色 + 两档描边 token、卡片去投影、撤紫色、换 Windows 蓝 ⑨ 字号三级 / 圆角 6·4 / 间距 4 栅格 | 判据 7、8 |
| **P3 能力补齐** | ⑩ Quick Look ⑪ 对比模式 ⑫ 最近使用 + 主色筛选 ⑬ 整理流水线 | 判据 6 |
**P0 单独就能回应"内容太多"。建议 V1.0 交付 P0 + P1**，P2 随后，P3 按价值序推进（Quick Look 优先级最高）。

## 12. 简报 §8 八问的明确回答

**Q1 主页信息架构？** 2 栏常驻（左导航 + 中内容）+ 第 3 栏按需（右详情）。常驻：导航、搜索、视图/密度、导入入口。按需：筛选条件、详情、结果提示、多选操作。粒度上只规定"字段属于哪一层"，写成配置数据，不规定像素。

**Q2 卡片几项信息？** 3 项：封面、名称、色标。扫视的判定依据只有图像与名字，其余是事后确认项；类型在左栏上下文中是冗余。其余下沉到 hover 浮层与详情面板。

**Q3 「扫」和「查」该不该分成两种视图？** **该分，但区别不在"网格 vs 列表"，而在"意图档"。** 网格内分扫/看/查三档（152/200/240）承担扫与看；列表只承担"查"：多列、可排序表头、固定 40px 行高、字段全开。列表不是网格的另一种排布，是查账工具。

**Q4 详情面板形态？** **按需抽屉 + 可钉住**（默认覆盖不挤压），理由见 §4。代价：钉住时挤压内容区 320px——但那是用户主动选择的结果。

**Q5 筛选/排序/视图放哪里？怎么避免横跳？** 四入口固定在中栏头右侧、顺序恒定；筛选维度收进 popover；激活条件以 chips 落在第二行；**维度不可用则置灰不删除**——最后这条是横跳的根治手段。

**Q6 密度取向？** **更多更小**，但"看清"另开专路（hover 大图 / Quick Look / 详情）。素材浏览是排除法，排除速度取决于同屏候选数；1,284 项在 12 张/屏下要滚 107 屏，任务不可完成。硬边界是不缩封面。

**Q7 没想到但该有的？** Quick Look、对比模式、最近使用、按主色筛选、整理流水线、键盘 Advance、渐进封面、库漂移指示（详见 §9）。明确不做：仪表盘、标签云、常驻 AI 入口。

**Q8 第一刀切哪里？** **切空间，不切视觉**（P0）：右栏改抽屉、左栏可折叠、卡片削字段、密度重标定。拥挤感来自空间分配与信息权重，翻新视觉不解决它。

## 13. 需要拍板的两件事
