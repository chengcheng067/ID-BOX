## 0. 产品一句话

ID BOX = ID 系列本地素材管理器。把知末 / Crystal 等站点下载的模型与材质压缩包拖进来，自动解压、剔杂质、按行业分类归档，快速找到、预览、拖进 SU / D5。

- 多选浮出操作条：指派分类 · 删除
- **资产卡（网格）封面框：一律 4:3 + `object-contain`**
  - ⚠️ **2026-10-22 反转**：此处原为「材质类预览框 1:1（用户拍板）」。1:1 修好了球图被裁切，
    但同一网格里方块卡比 4:3 卡更高 → 卡片标题被推下去、同一行高低不齐（用户原话「这个模型的名字

    留白用卡片底色，标题全部对齐且球图不被裁。详见 `docs/25` TODO-5。

## 2. 资产流转（数据层已有，UI 需遵守）

```
拖入压缩包/单图 → 磁盘预检 → 解压（GBK 嗅探重试）→ 剔杂质（微信扫码/推广/说明）
→ 递归下钻定 contentRoot 与资产名 → 定大类 → 落盘 <大类>/未分类/未分类/<资产名>
→ 缩略图（材质=Preview.png / 模型=SKP 内嵌 / 兜底=SU 图标）→ 原包进回收站
→ 浏览 → 指派分类 → 拖出 SU/D5 / 双击 reveal → 删除（确认+5s 撤销）
```

## 3. 材质模块（v0.1.2 反馈第 3 条，用户拍板方向）

### 3.1 封面与缩略图：**优先用包内自带的官方渲染图**

用户原话：「压缩材质包里面，实际上会给一个他们渲染好的材质球，所以我们普通的贴图才需要材质球的渲染……我更偏向于材质球的显示，是右侧文件夹里自带的这个渲染出来的展示效果」。

**实现规则（按优先级）**：
1. 包内命名含 `Preview/预览/封面` 的图片（如 `Brick_Rough_vh1sbjl_surface_Preview.png`）→ 直接当封面/缩略图
2. 包内其他明显是"成品渲染图"的图片（单张大图、非 PBR 槽位命名）
3. SKP 内嵌预览 / 包内预览图（模型的规则）
4. 都没有 → 类型图标占位

**我们自己的 three.js 渲染球降级为可选功能**：仅当包内**没有**任何成品渲染图、且贴图槽位识别齐全时才渲染；且渲染结果同样存成 JPG 进网格（不开实时 WebGL）。

### 3.2 详情面板：文件按槽位分组展示（用户原话：「点进去能看到哪个是法线贴图、哪一个是 AO 贴图」）

```
文件（8）
├─ 基础色 Albedo
│    vh1sbjl_2K_Albedo.jpg        4.1 MB
├─ 法线 Normal
│    vh1sbjl_2K_Normal.jpg        6.8 MB
├─ 粗糙度 Roughness
│    vh1sbjl_2K_Roughness.jpg     1.7 MB
├─ 环境光遮蔽 AO
│    vh1sbjl_2K_AO.jpg            2.7 MB
├─ 置换 Displacement
│    vh1sbjl_2K_Displacement.jpg  702 KB
│    vh1sbjl_2K_Displacement.exr  13.6 MB
├─ 元数据
│    vh1sbjl.json                 412 KB
└─ 预览
     Brick_Rough_…_Preview.png    959 KB
```
- 每行可单独拖出（贴图/HDRI 场景高频操作）
- 识别不进槽位的文件归「其他」组，不丢弃

### 3.3 调参渲染接口（可选功能，用户主动提出）

用户原话：「你是否要给我一个接口，让用户自己选择这个材质的反光以及凹凸，让它自己在我们的浏览器里面渲染一次材质，然后点保存呢？」

- 入口：详情面板预览区「自定义渲染」按钮
- 参数（第一版只放两个）：**反光强度（roughness 倍率）**、**凹凸强度（normal/displacement 倍率）**，滑块实时预览
- 「保存」→ 离屏渲染一帧存 JPG → 设为该资产封面（`coverSource='manual'`）
- 底层能力已有（three.js MaterialBall 组件 + 离屏渲染存 JPG），**只需加参数滑块与保存按钮**

### 3.4 材质预览框比例

**网格卡片：一律 4:3 + `object-contain`**（2026-10-22 反转，原为 1:1；理由见 §1.3）。
**右栏详情面板的封面区仍是 1:1**，本次未改——右栏是单条展示、不存在跨卡片的标题对齐问题。

## 4. 设置界面（v0.1.2 反馈第 6 条，参照 ID Plan 结构）

**结构**：模态弹窗 = **左侧分类 tab + 右侧内容区**（ID Plan 同构，风格自定）。

```
┌─ 设置 ──────────────────────── ✕ ┐
│ 外观        │  （右侧内容区）        │
│ 导入        │                      │
│ 库与分类     │                      │
│ 数据与备份   │                      │
│ 高级        │                      │
│ 关于        │  ID BOX v0.1.2       │
│            │  （版本号显示在这里）    │
└────────────────────────────────┘
```

| tab | 内容 |
| --- | --- |
| **外观** | 主题（浅色/跟随系统，深色留位） |
| **导入** | 原压缩包处置三档（回收站默认/彻底删除/保留）；并发数；**重新扫描按钮**（从顶栏移入，见 §1.1-Q1） |
| **库与分类** | 库路径（显示 + 更改）；分类体系说明（跳转 docs/06 词表）；7-Zip 状态与路径 |
| **数据与备份** | 索引导出/导入；缩略图缓存（数量/体积/清除） |
| **高级** | 长路径支持说明（Windows 260 限制）；日志目录打开 |
| **关于** | **版本号（醒目显示）**、检查更新（留位）、开源许可 |

**版本号要求**：设置「关于」tab 内显示 `ID BOX v<版本>`；如可行，左栏底部库路径旁也显示小字版本。

## 6. 待用户确认的问题（一次一个，不阻塞 UI Agent 起稿）

- **Q1**：重新扫描是「移入设置」还是「留在顶栏」？用户原话「将重新扫描显示在顶栏，并让其进入设置」有歧义，我按「移入设置」写了。
- **Q2**：自动分类——用户反馈「并没有主动分类一级二级」。当前设计是「导入零打断，落未分类，事后指派」。可选：a) 按文件名/来源匹配词表自动预分类（能匹配的落类，匹配不到的仍进未分类）；b) 维持现状；c) 接本地模型智能分类（成本高）。**建议 a**。
- **Q3**：多张图片同时拖入时，各自独立成资产，还是合并为一个贴图组？

## 7. 视觉方向（给 UI Agent 的风格 brief）

- 参照**结构**：ID Plan（左栏导航 + 设置弹窗左侧 tab），**但风格重构，不要紫色/蓝色系**
- 用户审美基因：**安静的自然系高级感**——暖中性底、克制用色、真实阴影分层、紧凑信息密度
- **禁**：玻璃拟态/backdrop-blur、渐变滥用、高饱和点缀、圆角过大的玩具感、紫色系
- **要**：暖灰/暖白底 + 单一低饱和强调色（建议暖褐/陶土系，呼应材质预览的暖调）、小信息用 chip 不用色块、类型徽标克制
- 参照产品气质：Blender 资产浏览器、D5 资源库、PureRef 的冷静感
