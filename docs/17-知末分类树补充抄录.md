# 知末分类树补充抄录（v1.0.10 事实来源）

> **采集时间**：2026-10-20
> **采集方式**：用真实浏览器（用户本机 Edge，**已登录态**）从 `su.znzmo.com` 素材库的**分类筛选树**逐节点读取。
> **权威口径**：知末的**商品详情页没有「所属分类」字段**，搜索页也**没有分类 facet**，
> 因此无法从单个商品反查分类；本文件一律以**分类节点页 URL 的 `<title>`** 作为权威。
> **本文件地位**：`docs/05-知末分类词表-原始抄录.md` 的**补充册**（不替代、不改写 05 的任何一行）。
> 凡与本文件冲突处，以本文件（更新、且为节点页实证）为准，但**必须先在 `docs/06` 记一条修订**再改代码。
>
> **核心结论（本次最重要的发现）**：**知末的分类树是三级，我们此前只抄到二级**。
> 此前被记为"知末没有这些类目"的 6 个词（屏风 / 隔断 / 花瓶 / 绿植 / 边几 / 卡座），
> 实际都存在于**第三级**。这解释了"词表匹配不上"的真正原因，不是站方缺类目。

### 4.1 由节点名派生的"中心语"形式（无独立节点 URL）

站方节点名是**并列复合词**，但真实资产命名常只说其中一个中心语，故归并表同时收了派生形式：

| 派生词 | 由哪个节点派生 | 归并到 |
| --- | --- | --- |
| 花瓶 | `花瓶花艺` | 软装陈设 / 摆件 |
| 边几 | `边几角几` | 家具 / 茶几 |
| 卡座 | `卡座沙发` | 家具 / 沙发 |

> 这些是**构词法派生**，不是新类目；落到落盘枚举里仍是上级二级，不会多出目录层级。

## 6. ⚠️ 误抄警示：商品详情页底部的是**适用场景标签，不是分类**

商品详情页底部会出现「艺术隔断 / 玄关 / 博古楼」这一类的词串。
那是**适用场景标签（场景 tag）**，**不是分类节点**，不在分类树里，也没有节点页 URL。
**禁止**把它们抄进词表——它们既不属于任何一级，也会持续膨胀、互相重叠。

判据（写死在这里，防止后人再犯错）：
1. 能在分类筛选树里点到 → 分类；
2. 有独立节点页 URL 且 `<title>` 含完整父链 → 分类；
3. 只在商品详情页/搜索结果里出现的词串 → **标签**，不入词表。

## 7. ⚠️ 重要限制：`3D模型` 频道与 SU 频道的一级**不一样**

`3D模型` 频道独有（SU 频道没有）的一级：**`装饰品` / `用品·器材` / `窗帘布艺`**；
反过来 SU 频道有而 3D模型 频道没有的：`厨卫五金` / `电器·器材`(写作 `用品·器材`) / `家装户型` /
`SU材质` / `美陈装置` / `标识广告` / `交通工具` / `展厅·展台` / `舞台`。

**本项目词表目前以 SU 频道为准**。两个频道的一级**混用会导致类目对不上**
（例如 3D模型 频道的「装饰品」在 SU 频道并不存在，若混入会造出一个永远不会被 SU 资产命中的一级）。
将来若要同时支持 3D模型 频道，必须**按频道分册**（与 `CHANNEL_LEVEL1` 的做法一致），
**禁止**把两个频道的一级拍平成一个并集。

## 8. 本轮（v1.0.10）在代码里的落地

只加不改，落盘结构（大类 / 一级 / 二级 / 资产）**零变化**：

1. `src/shared/taxonomy.ts` · `LEVEL2_MAP['硬装构件']` 追加 `屏风隔断` / `装饰线条` / `电梯`（3 项，
   既有 11 项一项未删未改名）。
2. `src/shared/taxonomy.ts` · 新增 `LEVEL3_ALIAS`（`Level3Alias` 接口）——三级节点 → 上级二级的
   **归并表**，每行带站方出处。归并**只影响匹配**，不改落盘枚举。
3. `src/shared/autoClassify.ts` · 把 `LEVEL3_ALIAS` 接进第一轮匹配：命中规则与二级词条完全一致
   （CJK token 后缀/全等、最长优先）；命中后 `category2` 取归并表指定的二级、`matchedTerm` 记
   实际命中的词，并附加可选字段 `matchedLevel: 'l3-alias'`（二级原文命中**不写**该字段，
   保持既有对象形状，存量调用方零影响）。
4. 等长时**二级原文优先于三级归并**（候选数组把二级放前面，`pickBest` 只在严格更长时替换）。

### 8.1 顺带补上的一个更严重的洞：kind ↔ 一级频道一致性闸门

实地核查时发现：`isKnownCombo()`（`taxonomy.ts`）只校验"一级/二级是否成对"，
**不校验这个一级属于哪个频道的词表**，而且全仓没有调用方 —— 于是
`屏风贴图` 这种名字会命中**模型频道**的一级 `硬装构件`，贴图资产落进 `材质/硬装构件/…`，
一个大类下出现别的频道的一级。

这个洞本来就有（任何贴图只要名字尾部是「门」「窗」「家具」等模型频道一级词都会中），
**归并表把它放大了**（新增了 `屏风/隔断/花瓶/边几/卡座/绿植` 一批高命中的三级词）。

修法（`taxonomy.isLevel1AllowedForKind(kind, level1)`，纯函数 + 单测）：
- 用现成的 `CHANNEL_LEVEL1` 判断 `category1` 是否属于当前 `kind` 的频道；
- **不属于 → 丢弃整个 hit，落 `未分类/未分类`**（宁可不分，不可分错）；
- `texture` 与 `material` 落盘大类同为「材质」，但一级词表**各按各的册**校验，不混用；
- `hdri` / `other` 没有一级词表 → 一律 `false`；
- 闸门加在 `src/main/importer.ts` 的两处 `autoClassify()` 之后（压缩包导入 + 单图直导），
  逻辑只有一份（共享纯函数），不在两处重复实现。
