# 23 · 知末封面自动化 —— 可行性结论

> 2026-10-22。对应 `docs/21` 需求 B（用 ID 去知末抓主图当封面）中列出的 4 个「开工前必须摸清」的问题，本文逐条给出实测结论。
> 证据来源：两路独立实测 + 主理人独立复核，原始记录在 `docs/probe/`。
> 状态：**技术可行性已验证（A 档绿灯），待产品拍板实施形态。**

## TL;DR

1. **能成，且不需要登录、不需要签名、不需要 cookie。** 裸 ID 一跳拿详情页、二跳拿图，主进程 `fetch` 即可。
2. **水印不是死结。** 调研初始结论是「要么接受水印、要么裁掉画面下半部」，实际存在第三条路：同一张图在另一个图床有 **400×300 无水印完整版**，7/7 命中。
3. **分辨率是有代价的**：无水印版封顶 400×300；1600×1144 的大图必然带水印（水印烤在 OSS 对象里，非前端叠加）。

## 一、逐条回答 `docs/21` 的四个未知

### 1. URL 规则（原：不能凭猜）

**成立，且比预期简单。**

```
详情页  https://su.znzmo.com/sumoxing/{ID}.html          # 固定入口，redirect: follow
图片    从详情页 __NEXT_DATA__.props.pageProps.res.mainImageUrl 取
```

- **站点 301 双向归位**：模型 ID 留在 `su`，材质 ID 自动跳 `tietu`。**不需要先判断资产是模型还是材质**，也不需要维护两套前缀。
  （真实浏览器复核过地址栏跳转，非 curl 特例。）
- 7/7 个本机真实 ID 命中，页面 `title` 与本地资产名一致。
- ⚠️ `caizhi/{id}.html` 是老 ID 的 404 陷阱，**不要用**。
- ⚠️ **主图 URL 不能由 ID 拼出**：文件名是「上传毫秒时间戳_4位随机数」，必须过详情页这一跳。

### 2. 主图在哪（原：og:image？）

- **全站没有 `og:image`**，抓 og:image 的方案直接作废。
- 首选：`script#__NEXT_DATA__` → `props.pageProps.res.mainImageUrl`（1600px 带水印）/ `listImageUrl`（400px 无水印）
- ⚠️ **JSON-LD `ImageObject.contentUrl` 不能用来取封面**：实测它指向 `image2` 的 1600px **带水印**大图（`1200166260` 已核）。
  它只能用作"资产是否有效"的第二道判据（`__NEXT_DATA__` 与 JSON-LD 两条路径都解析不出图 URL → 判失效）。
- 顺带（后续可选，本批不做）：JSON-LD 的 `BreadcrumbList` 带频道名（`SU模型` / `贴图材质`）与分类面包屑，未来可用于校验自动分类。
- DOM 兜底 `div[class*="ThumbnailImage__mainImageContent"] > img` 的类名带构建 hash，**不稳，不要当主选择器**。

### 3. 反爬（原：要不要登录）

**不需要登录。**

- 未登录访客的 SSR HTML 里就已经是 1600px 直链。
- 页面上的「登录后查看完整详情」是**纯前端 CSS 遮挡**（弹窗/淡化层），不改变已下发资源。
  → **不需要做「内置浏览器手动登录一次」那套产品设计。**
- 图片 CDN（阿里云 OSS）**不校验 cookie / Referer / UA**：无 Referer、假 Referer（`example.com`）、空 UA 全部 200 且字节相同。
  响应头还带 `Access-Control-Allow-Origin: *`。
- 累计约 75 次请求、20 个资产串行 12.5 秒：0 次 429/403/验证码。站点有 WAF，但常规详情页 GET 不触发。
  → 仍建议温和节流：并发 ≤3、间隔 250ms、单批上限 50。

### 4. 两个陷阱（原文档没预料到）

- **失效页有三种形态，状态码完全不可靠**：

  | 形态 | 特征 | 出现位置 |
  |---|---|---|
  | 软 404 | **HTTP 200** + 约 18KB + title「知末网」，无主图 | 数字 ID 不存在（最常见） |
  | 裸 Next.js 404 | 404 + 6~7KB + **无 title** | 路由不存在 |
  | WAF 品牌 404 | 404 + 7730B + 「云防护系统」 | **仅** `/caizhi/` 路径（我们不用这条路） |

  → 唯一成功判据：**解析出图 URL 且宽度 ≥200px**。
- **格式不定**：主图有 jpg 也有 png（实测 `1193950340` 的 list 图就是 PNG 400×300）。
  → 落盘必须嗅 magic bytes，正好现成有 `src/main/coverImage.ts: detectCoverImageFormat()`。

## 二、水印：三条路线实测对比

| 路线 | 来源 | 分辨率 | 水印 | 评价 |
|---|---|---|---|---|
| **A 大图** | `mainImageUrl`（`image2.znzmo.com`，`style/detail`） | 1600×1144 / 1600×952 / 1600×1600 | **模型**：底部约 37% 整片「知末」阵列（压着品牌 logo，裁掉会切到主体）；**材质**：全图平铺，裁不掉，浓度随上传者差异极大 | 清晰但不可用于干净封面 |
| **B 干净小图** | `listImageUrl`（`image6.znzmo.com`，`style/list`） | **400×300** | **无水印，构图完整** | ✅ 推荐作卡片封面 |
| C 裁剪 | A + OSS `crop` | 1600×~620 | 可去水印带 | 会切掉画面下半部，实测壁灯底座被切 |

**B 的关键证据**（主理人独立复核，7/7）：`listImageUrl` 与 `mainImageUrl` 指向同一个对象文件名，只是换了图床和样式；
`image6` 上的对象本身就只有 400×300，**加任何 resize 参数都出不了更大尺寸**（`w_1600` / `m_fill,w_800,h_600` 都返回 400×300）。

实测干净样张 7/7 已归档（肉眼确认无任何水印、构图完整，全部 400×300）：

- `docs/probe/samples/clean400-1200166260.jpg`（模型-壁灯）
- `docs/probe/samples/clean400-1186414883.jpg`（模型-挂画组合）
- `docs/probe/samples/clean400-1172815578.jpg`（材质-仿古砖）
- `docs/probe/samples/clean400-1193950340.png`（材质-红砖，**注意是 PNG**）
- 其余 3 个同目录

## 三、抓取配方（可直接落地）

```ts
// 伪代码：主进程，两跳
const page = await fetch(`https://su.znzmo.com/sumoxing/${id}.html`, {
  redirect: 'follow',
  headers: { 'User-Agent': 'Mozilla/5.0 (IDBOX cover fetcher)' },
  signal: AbortSignal.timeout(15_000),
})
const html = await page.text()
const json = JSON.parse(/<script id="__NEXT_DATA__"[^>]*>([\s\S]*?)<\/script>/.exec(html)?.[1] ?? 'null')
const res = json?.props?.pageProps?.res
if (!res?.mainImageUrl) return null            // 软 404：唯一可靠判据
const imgUrl = res.listImageUrl                // 优先无水印 400×300
             ?? res.mainImageUrl
const img = await fetch(imgUrl, { signal: AbortSignal.timeout(20_000) })
const buf = Buffer.from(await img.arrayBuffer())
// 交给 coverImage.ts：detectCoverImageFormat 嗅 jpg/png → validateCoverImage（≤20MB）→ 落盘
```

- 建议再加一道尺寸护栏：**宽度 < 200px 直接丢弃**（防止拿到占位图）。
- 顺带白捡的元数据（同一份 JSON，未来可用于分类/展示）：
  `version`（"sketchup 2014"）、`fileLength`（压缩包 MB，可校验下载完整性）、
  `propertyValue[]`（格式/风格/是否无缝）、`price`、`browseCount`/`downloadCount`。

## 四、建议的实施形态（待拍板）

**封面优先级**（现有四级回退：SKP 内嵌预览 > 包内预览图 > 占位图标）：

```
用户手动设置的 cover（最高，现有）
  > 知末无水印小图 400×300（新增）
  > SKP 内嵌预览 256px（现有）
  > 包内预览图（现有）
  > 占位图标（最低）
```

理由：SKP 内嵌预览实测**只有 256px 宽**且是 SU 视口灰白图；知末主图是渲染图，400px 且更像"封面"。
材质类**不需要**抓：本地 `.cover.jpg` 已是 1K 级的贴图本体，比知末图更准。

**触发时机**（三个选项，见下节问题）：导入后置任务自动抓 / 详情面板手动「从知末取封面」/ 两者都做。

**失败语义**：任何网络异常、软 404、超时、格式不符 → 静默跳过，保持现有封面，**绝不阻塞导入、绝不弹错**。

## 五、风险与合规

| 风险 | 评估 |
|---|---|
| 站点改版（Next.js 数据结构变化） | 唯一真实风险。必须做"取不到就静默降级"，且不支持时不能让导入变慢 |
| 版权 / ToS | 抓的是**付费素材的公开预览图**，只作本地个人库的封面展示、不对外分发 → 个人使用风险低；**若将来开源或对外分发库数据，需重新评估**，建议在文档里写明 |
| 频控 | 低。20 个串行 12.5s 无异常；仍按浏览器 UA 节流请求 |
| 分辨率上限 | 干净版只有 400×300，低于应用自身 `thumbMaxPx` 默认 480 → 卡片上会被放大约 1.2 倍，可接受；详情面板大图会略软 |

## 六、待拍板（1 个问题）

**抓取触发方式选哪个？**

- **A 只在导入时自动抓**（零操作，但已有资产不会补，且导入会多 0.5-1 秒/个后台任务）
- **B 只在详情面板给一个「从知末取封面」按钮**（完全可控，但要用户一个个点）
- **C 导入自动 + 手动可重取**（推荐：新资产自动有封面，老资产和抓失败的能手动补）
