## 0. TL;DR

用户反馈（原话）：「其实我们 idbox 原生软件的整体 UI 结构是挺好的，只不过现在进 SketchUp 的这一个，可以说你完全没有做 UI……而且现在也没有我们面板在 SketchUp 能快捷打开的工具栏按钮」。

我认账：之前把可搭鸭只用来定「文件格式 + 硬约束」，把它真正值钱的**「一个 SU 插件长什么样、怎么被打开」**整层漏掉了。当前面板是「带搜索框的文字列表 + 状态行」，数据/回调骨架是好的，但**没有壳**。

结论一句话：**照抄可搭鸭的「结构层」，照抄 ID BOX 原生软件的「视觉层」，两样都不照抄它的「载体层」**，另外补一个常驻工具栏按钮。

> **第一棒口径（用户 2026-11-05 拍板）**：不用静态 HTML 样张，**沿用 V0.2 的做法用 Ardot MCP 在画布里出设计稿**，你看过长相再点头，然后才由工程师照稿写 `panel.html`。详见 §9。

## 1. 三条会改变做法的事实

| # | 结论 | 标注 | 依据 |
| --- | --- | --- | --- |
| 1 | 可搭鸭截图里那个「材质库/模型库/灵感库」卡片网格 UI **很可能不在 `.rbz` 包里**：107 个 `.rb` 有 106 个是加密 IR，包内 5 html / 2 css / 2 js 全是参数面板 + 一张断网诊断页，全包中文 UI 词只扫到「客服」二字 → 主面板是**云端 web app 经 `set_url` 载入 SU 窗口** | **【推断·高置信】**，非已证实（不能 100% 排除 IR 用 `set_html` 动态拼 DOM，需真机核实） | `okducky-ui-structure.md` §1.4、§9.2；`load_failure.html` 全 323 行是代理/VPN/登录态诊断 |
| 2 | **ID BOX 原生视觉语言可以在「单个自包含 `panel.html`」里 100% 复刻**：`design-tmp/settings-redesign-v2.html` 已是活证据 —— 0 个 http(s) URL、0 个 `<link>`、0 个 `<script>`、0 个 CDN / `@font-face` / `url()`，图片全 `data:image/png;base64`，字体走系统字体栈，token 已翻译成一个 `<style>` 里的普通 CSS + 语义 class | **【查证】** | `idbox-ui-portable-spec.md` §0.1、§6.1；`settings-redesign-v2.html:3,12-112` |
| 3 | 可搭鸭的 `UI::Toolbar` / `UI::Command` / `add_item` / `add_action_callback` / `place_component` 调用点**全在加密 IR 里，零一手证据**；它另外用原生 DLL（`okducky_window.dll` 导出 `okd_make_titleless_window` 等）把 SU 窗口改成无边框圆角浮窗 | **【查证】**（加密状态 + DLL 导出）；**工具栏注册链只能按官方 API 反推 →【推断】** | `okducky-ui-structure.md` §2、§4.2、§5 |

### 由此推出「不照抄什么」

| 不照抄 | 原因 |
| --- | --- |
| 把主面板放公网云端（`set_url`） | 与 `docs/39 §4.1#2` **零网络**硬约束正面冲突；可搭鸭为此付出整页代理/直连域名/登录态重置/系统代理改写的代价 |
| 用原生 DLL 改无边框浮窗 | 与 `docs/39 §4.1#3` **零原生件**硬约束冲突；Win32 + Obj-C++ 两套，与 CEF 窗口结构强耦合 |
| `docs/32-UI设计方案-V1.0.md` 的色值 | 那是**推翻性提案、未落地**（`docs/32:12` 明确「推翻 Soft UI 与 Vibrancy」）。现状仍是 v0.2 的 Soft UI / Vibrancy + `#007AFF` |
| 把 `window.sketchup.*` 当作 ID BOX ↔ 插件的跨进程协议 | 它是 SU **进程内**桥；跨进程那层按 `docs/38 §5.2` 走本地 JSON 快照 |

| 层 | 做法 | 依据 |
| --- | --- | --- |
| **载体** | SU 原生 `UI::HtmlDialog` + `set_file` 指向包内本地 HTML；**不要** `set_url` 云端、**不要** DLL 无边框。深色顶栏由 HTML 自绘 | `docs/39 §4.2`；可搭鸭 §4.2 反向教训 |

## 3. 面板 UI 结构（六块，按原生复刻）

| # | 块 | 原生做法 | 当前 `panel.html` | 要做 |
| --- | --- | --- | --- | --- |
| ① | 顶栏 | 56px：Logo 方块 + `ID BOX` 字标 + 搜索 + 视图/密度分段控件 + 状态区 | 纯文字标题 + 计数 + 刷新按钮 | 补 Logo、tab、搜索收起态、分段控件、状态区 |
| ② | 左栏导航 | 216px：大类 + 图标 + 计数 + 选中态 + 分类树 + 底部 CTA | **完全没有左栏** | 整块新建：按 `kind`（模型/材质/HDR/CAD/其他）+ 分类树筛选 |
| ③ | 筛选 chips | 中栏头 chips + 下拉浮层 + 排序 | 只有一个搜索框 | 补 chips（全部/类型/分类）、排序 |
| ④ | 卡片网格 | `aspect-[4/3]` 封面、角标、名称、副信息、hover、选中 2px+对勾、密度三档 | **列表行**（名称 + tag + 路径 + 插入按钮） | 换成 `.grid/.card`；这是用户说「完全没做 UI」的核心 |
| ⑤ | 空态 / 错误态 | 40px SVG 空态 + 区分「库为空」与「筛选 0」+ 错误边界 | 结构有、全是纯文字 | 换皮 + 补内联 SVG + 分级 |
| ⑥ | 底部状态栏 | 44px 通栏、绿圆勾、结果文字、撤销胶囊、文档流挤压行 | 26px 纯文字 | 升级到 44px + 图形 + 胶囊 |

**缩略图**：索引快照已带 `thumbRel`（相对 `manifest.thumbsRoot`，`docs/39:77/96/115`），所以卡片可以显示真实封面，不是只能画占位图标。
- **【待核实】**：SU `HtmlDialog` 里能否用 `file:///` 加载本地图片（`thumbsRoot` 是绝对路径，需 Ruby 一并推进 payload）；`vault://` 是 Electron 自定义协议，SU 里未必可用。
- **【建议】双轨**：`thumbRel` 有值且可加载 → `<img>`；否则按 kind 用内联 SVG 占位（`IconBox/IconMaterial/IconHdr/IconCad/IconOther`）。

**必须保留的骨架**（`panel.html:10-23`、`:202-208`、`:388-445`）：零网络 / 零上报 / 纯前端内存过滤 / 只读；`sketchup.ready()` `refreshIndex()` `insertRecord(id)` 与 Ruby 注入 `window.IDBOX.render(payload)` `setStatus(obj)` 的契约**只增不删**。补 UI 只是换 `<style>` 与 `<body>`，不重写数据层。

## 4. 工具栏按钮（新增，本批的重点缺口）

【推断】按 SketchUp 官方 API 反推的调用链（可搭鸭的对应调用点物理不可读，**不要对外说成"可搭鸭就是这么做的"**）：

```
根 rb 或 main.rb 加载时：
  cmd = UI::Command.new('ID BOX 素材库') { IDBoxPanel::Panel.instance.toggle }
  cmd.small_icon = <idbox_panel/assets/toolbar_idbox.svg>   # 绝对路径，由 Paths 解析
  cmd.large_icon = 同上
  cmd.tooltip = '打开 ID BOX 素材库'
  cmd.status_bar_text = '在 ID BOX 本地库里搜索并插入模型'
  tb = UI::Toolbar.new('ID BOX')
  tb.add_item(cmd)
  tb.restore            # 恢复用户上次的显示/停靠位置
```

- 图标资源：**【查证】** 可搭鸭 23 个 svg / 22 个 pdf 严格成对，是跨 Win/macOS 的工具栏矢量图标；我们 V1.0 只需 1 个，做 SVG + PDF 各一份，stem 与 rb 同名。
- 还要处理：面板已开时按钮应 `bring_to_front`、关闭后可再开（`visible?` 判定），而不是每次 new 一个窗口。
- **【待核实】**：SU 2021+ 对 `small_icon` 的格式要求（svg 是否直接可用 / 是否需要 png）、`toolbar.restore` 在首次安装时的行为。→ 真机首验第一条。

## 5. 文件结构（改动清单）

```
plugin-src/
  idbox_panel.rb                      ← 保持：只注册扩展 + 元数据
  idbox_panel/
    main.rb                          ← 拆：入口/注册工具栏/装配
    panel.html                       ← 重写：<style> + <body> 按原生换皮；<script> 契约保留
    lib/
      paths.rb                       ← 从 main.rb 抽出（已有 Paths 模块）
      loader.rb                      ← 从 main.rb 抽出（数据读取 + SHA256 校验）
      panel_dialog.rb                ← 从 main.rb 抽出（HtmlDialog 装配 + 回调注册）
      panel_callback.rb              ← 新：add_action_callback 集中分发
      toolbar.rb                     ← 新：UI::Toolbar / UI::Command
    html/                            ← 【可选】若 CSS/JS 外链，放这里（set_file 用相对路径）
    assets/
      toolbar_idbox.svg / .pdf      ← 新：工具栏图标（成对）
      icons.svg                     ← 新：内联 SVG 精灵表（12 支，从 icons.tsx 移植）
```

> 说明：`docs/39 §4.2` 原本约定 `lib/`「V1.0 只立目录、不产出文件」。本次因为 UI 层进来、单文件 main.rb 已 1100+ 行，建议改为**实际拆分**；这是一条需要你点头的口径变更。

## 6. 硬约束（复刻 UI 时不得放开）

| # | 约束 | 出处 |
| --- | --- | --- |
| 1 | 零网络：无 http/CDN/外链字体图片/XHR/fetch/WebSocket | `docs/39 §4.1#2`、`panel.html:10` |
| 2 | 零原生件：不 require .so/.bundle/.dll，不用第三方 gem | `docs/39 §4.1#3` |
| 3 | 零 token / 零端口 / 零后台服务（只有面板打开时的 3 s 轮询） | `docs/39 §4.1#4` |
| 4 | 不解压、不读压缩包；不自删、不自升级 | `docs/39 §4.1#5/#6` |
| 5 | 纯读方；**唯一例外**：建窗失败时写 `%TEMP%\idbox_panel_diag.txt`（用户 2026-11-05 批准） | `docs/39 §4.1#7`（v1.5 已标注） |
| 6 | `.rbz` 根恰好两项；包内 code 单一模块、无全局变量；Ruby 2.7 写法；门槛 SU 2021+ | `docs/39 §4.2/§4.3` |
| 7 | 不照抄 Tailwind 类名（无构建不生效）、不引 `Sarasa Gothic SC` 字体文件、不做 three.js/虚拟滚动/动效 | `idbox-ui-portable-spec.md` §6.2 |

## 7. 明确不做（V1.0）

- 云端主面板 / 账号 / 登录态 / 代理诊断
- 无边框圆角浮窗（原生 DLL）、窗口自拖拽/自最大化
- 面板内真拖到 SU 视口（用户已裁定「点一下即插入」）；材质取用仍等 D2 探针结果
- 主题切换 UI（V1.0 跟随系统 media query 即可）、密度三档、Quick Look
- 面板内缩略图重渲染 / three.js 材质球
