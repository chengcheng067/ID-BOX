# 33 - Eagle 预研笔记（服务 V1.0 迭代）

> 调研对象：https://cn.eagle.cool/ （Eagle 4.0.0 Build23）
> 目的：为 V1.0 UI/交互迭代（docs/31 需求简报 + docs/32 设计方案）提供对标输入。
> 性质：官网级预研（未深测软件本体），只提炼与 ID BOX 相关的能力。

## 一、Eagle 是什么

素材管理桌面软件（Windows/macOS），面向设计师收集海量图片/设计参考。四大支柱：**收藏 → 整理 → 搜索 → 浏览**，外加 AI 动作与插件系统。定位是"个人素材库中枢"，与 ID BOX"本地建模/贴图素材库"同属素材管理赛道，但 Eagle 偏"收集端"（从网上抓），ID BOX 偏"资产端"（本地渲染、命名、重排、封面）。

### B. Eagle 有、但 ID BOX 场景不适配的（不抄）

| Eagle 能力 | 不抄理由 |
|---|---|
| 浏览器扩展/穿透锁右键/批量抓取 | Eagle 是收集端；ID BOX 资产已在本机，无抓取需求 |
| AI 搜索（以图找图/语义搜索） | 本地离线工具，模型成本高；3D 素材以"分类路径 + 命名"检索已够用，语义搜索可远期 |
| 随机模式 | 灵感工具属性，建模素材库不需要 |
| 插件系统 | 超出 V1.0 范围，远期再说 |
| 十多种维度进阶筛选器全铺开 | 正是 docs/32 诊断的"平权"反面教材——Eagle 面向海量收集可以铺，ID BOX 控件应"置灰而非移除"、按需展开 |

### C. 对 V1.0 设计输入的直接结论

1. **Quick Look（空格预览）从"可选"升级为"推荐进 V1.0"**——Eagle/桥/Page 均标配，用户学习成本为零，且正好补偿密度提高后的预览损失。
2. **悬停预览列为 V1.1 候选**——球图/贴图可 hover 出大图或帧序列，但需渲染缓存配合，不塞进 V1.0。
3. **布局模式保持"统一网格 + 密度分档"**，瀑布流不进 V1.0（3D 资产宽高比差异小，瀑布流收益低）。
4. **全局快速切换器（Ctrl+P/Ctrl+K）列为 V1.0 可选项**，待用户拍板。
5. **筛选器收口方向获对标支持**：Eagle 那种"筛选器全部常驻铺开"恰恰是我们要避免的形态，佐证 docs/32 的"中性工具面 + 按需上下文"。
