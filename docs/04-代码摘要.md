## 2. `src/shared/`（纯函数层，T02）

### 2.1 `encoding.ts` 🆕

- **职责**：解压后判断"文件名是否乱码"，给出整包判定与样本。PRD **P0-2 / K1**。
- **关键签名**

```ts
export const MOJIBAKE_RATIO_THRESHOLD = 0.2
export const MOJIBAKE_SUSPECT_MIN_CHARS = 3
export function hasReplacementChar(s: string): boolean
export function isMojibakeSuspect(s: string): boolean
export function scanNames(names: string[], opts?: { ratioThreshold?: number; maxSamples?: number }): NameScan
export function isScanMojibake(scan: NameScan, opts?: { ratioThreshold?: number }): boolean
// NameScan { total; suspicious; ratio; hasReplacement; samples }
```

- **判据**：① 含 `U+FFFD`（UTF-8 解 GBK 字节的典型产物，最强信号）；② **≥2 个连缀**或**整串 ≥3 个**"可疑字符"（拉丁扩展 / 上下标 / 弯引号 / € ™ 等）。
- **已知边界**
  - `Café Crème.skp`（2 个分散重音）**故意不判乱码** —— 单靠比例会误伤合法外文名（R8）。
  - **UTF-8 字节被当 GBK 解**会产生形如"鐜颁唬琛ｆ煖"的**合法 CJK 乱码**，本嗅探器**检测不出来**（无 U+FFFD、无拉丁字符）。这是已知盲区，靠 `codepage:'auto'` 时先读 zip 的 UTF-8 flag 规避。
  - 阈值 0.2 为经验值，QA 若发现误报可在 `scanNames` 的 `ratioThreshold` 调。

### 2.2 `skpVersion.ts` 🆕

- **职责**：读 `.skp` 前 128 字节解析 SketchUp 版本。PRD **P0-15 / N1**。
- **关键签名**

```ts
export const SKP_HEAD_BYTES = 128
export function parseSkpVersion(head: Uint8Array | ArrayLike<number> | null | undefined): SkpVersionInfo | null
export function suLabel(major: number): string
// SkpVersionInfo { major; minor; build; raw; label }
```

- **逻辑**：magic `FF FE FF 0E` → 跳过 BOM 后按 UTF-16LE 解码 → 先试 `/\{(\d+)\.(\d+)(?:\.(\d+))?\}/`，无花括号时要求串里出现 `SketchUp` 再用宽松正则兜底。`major ≥ 17 → SU ${2000+major}`，`≤16 → SU ${major}`。
- **已知边界**：**任何失败都返回 `null`（静默降级）**，不抛错、不阻断导入。magic 不符 / 空 Buffer / 随机字节 / 截断头 / null 输入全部安全返回 null。

### 2.3 `space.ts` 🆕

- **职责**：磁盘空间预检的**纯计算**部分（不含 IO）。PRD **P0-3 / D3**。
- **关键签名**

```ts
export const DEFAULT_SAFETY_FACTOR = 1.2
export function requiredBytesFor(o: SpaceInput): number   // uncompressed × factor + archive
export function evaluateSpace(freeBytes: number, o: SpaceInput): SpaceCheck
export function humanGB(bytes: number): string            // → '12.4 GB'
// SpaceCheck { ok; freeBytes; requiredBytes; uncompressedBytes; archiveBytes; message }
```

- **已知边界**：`evaluateSpace` 是**纯函数**，不做任何 IO；取 freeBytes / uncompressed 由 `main/disk.ts` 负责。取不到可用空间时按 0 处理 → 判为不足（宁可拒，不可漏）。

### 2.4 `classify.ts` 🔧

- **职责**：扩展名归类 + **封面四级回退** + 主模型文件选择。PRD **P0-8 / C3 / P0-14**。
- **关键签名**


### 3.2 `disk.ts` 🆕 — PRD **P0-3 / D3**

```ts
export async function freeBytesOf(dir: string): Promise<number | null>   // fs.statfs；目录不存在时向上回溯
```

**取值链路**：`7z l -slt` 求和 `Size = N`（精确）→ adm-zip `entry.header.size`（精确）→ `原包 × 3`（保守估算，`exact:false`）。任何一步失败都**不抛错**，退化为保守估算。

### 3.3 `extractor.ts` 🔧 — PRD **P0-2 / C1 / C2**

```ts
export class ExtractionError extends Error { readonly kind: ErrorKind }
export type ErrorKind = 'password'|'corrupt'|'unsupported'|'no7z'|'oversize'|'timeout'|'other'
export async function extractArchive(src, dest, opts: ExtractOptions): Promise<ExtractResult>
export async function listUncompressedBytes(src, opts): Promise<UncompressedInfo>
// ExtractOptions { sevenZipPath; codepage; timeoutMs; maxBytesForJsFallback }
// ExtractResult  { engine:'7z'|'admzip'; codepage:'gbk'|'utf8'; mojibake; suspiciousRatio; samples }
```

- **码页三级回退**：`-mcp=GBK` → `-mcp=936` → 不带参数（老版 7-Zip 不认 `-mcp`，U1）。
- **换码页重解**：首解为 `gbk` 且嗅探命中乱码 → 清空 dest → UTF-8 重解一次。**首解为 `utf8` 时不再回退 GBK**（否则与"utf8 → 标疑似乱码"的契约矛盾）。
- **adm-zip 兜底**：仅 `≤ maxBytesForJsFallback` 的 zip；`resolveAdmZipMode` 在 `auto` 下先读 central directory 的 UTF-8 flag 决定 gbk/utf8，看不出才按 GBK。
- **白名单收敛**：只留 `zip / rar / 7z`（`.tar/.gz/.tgz` 已移除）。
- **`execFile` 加 `timeout`（默认 10 分钟可调）+ `maxBuffer` 32MB**；stderr 摘要截断 200 字符，**绝不把 32MB 输出灌进 UI**。

### 3.4 `importer.ts` 🔧 — PRD **P0-1 / P0-3 / P0-4 / P0-5 / P0-7 / P0-15**

```ts
export const DEFAULT_CONCURRENCY = 3
export interface ImportDeps {
  libraryDir; sevenZipPath; archiveDisposal; defaultSource; codepage
  timeoutMs; maxBytesForJsFallback; spaceSafetyFactor; concurrency
  ensureThumb?: (assetId: string, coverAbs: string | null) => Promise<string | null>
  disposeArchive?: (src: string, mode: ArchiveDisposal) => Promise<void>
  emit: (ev: ImportEvent) => void
}
export async function importPaths(paths: string[], deps: ImportDeps): Promise<Asset[]>

```

- **空间预检先行**：`checkSpaceFor` 不通过 → 直接 emit error（带 `needBytes`/`freeBytes`）并 `return null`，**不建 staging、不产生半成品**（D3）。
- **并发**：自实现 `mapWithConcurrency`，**上限 ≤3**；带 `onError` 兜底，**单个任务抛错不中断整批**（US-1 / G1）。
- **依赖注入**：`ensureThumb` 与 `disposeArchive` 都是**可选注入**，保证 importer **不 import electron**、可在 vitest 里单测。
- **staging 清理**：`finally` 里删 `<uuid>` 子目录，再 **best-effort 非递归 `rmdir('<库根>/.staging')`** 清空壳 —— 绝不用 `recursive:true`（并发中会端掉兄弟导入的 staging）。

### 6.1 `moveAssetCategory` self-target 守卫（真 bug）

**现象**：对「已在目标分类」的资产再指派同分类时，`readdir(parentDir)` 会读到资产自己的目录名 →


`MoveCategoryResult` 新增 `moved: boolean`（true = 实际移动；false = self-target no-op），
`AssignCategoryResult` 同步透传。**渲染层 `assignCategory` 消费点未动**（T07 代码），`moved` 字段暂未消费 ——

### 6.2 `migrateLayout` 的 `ok` 回传最终落盘值

（否则改过名的记录 folder 与磁盘不一致）。

- `relFolder` 的修正只动**末段**（资产名），父链（大类/未分类/未分类）不变。
- 顺带加了同类的 **from === to 幂等守卫**：源与目标是同一路径 → 计入 `ok` 原样返回，不抛错也不算失败。
- `store.ts` 的 `migrateLegacyLayout` 消费点已改为遍历 `result.ok` 取 `done.to` / `done.relFolder`，
  并删除了原来按 id 反查计划值的 `moveById` 映射（不再需要）。

### 6.3 rescan 的 `onIgnored` 上报到渲染层（RA6 闭环）

## 6A. DEF-01 / DEF-02 修复（QA 第 1 轮打回）

### 6A.1 DEF-01（致命）：装有 7-Zip 的机器上所有导入必失败

**根因**：`7z x -mcp=GBK` 报 `Can't open as archive`（`-mcp` 对**解压**不受支持），而旧三级回退的触发条件
`isUnknownSwitch` 只匹配 `unknown switch/incorrect command line` 等措辞，匹配不了这个错误形态 →
第一次尝试直接抛错，`-mcp=936` 与无参数尝试永远轮不到。**248 条单测全绿也测不出**：所有解压用例都在
`sevenZipPath: null` 下走 adm-zip 分支，7z 主路径零真实覆盖。

**修复后的 7z 参数策略（主理人裁定，已实现）**：

```
裸参数 x -y -o<dest> -- <src>          ← 首选。Windows 版 7z 默认按系统 ACP 解不带
  │                                      UTF-8 flag 的文件名，中文系统(936)零乱码（QA V2 实测）
  ├─ 失败且 kind ∈ {password, corrupt, timeout}
  │    → 直接抛可行动错误（换码页重试无意义，也避免把 GB 级包解两遍）
  ├─ 失败且其他（含 "Can't open as archive"）
  │    → 兜底重试 -mcp=GBK（老版本 7z 可能认）；**该次失败被兜住**，绝不向外抛
  └─ 成功 → scanNames() 乱码嗅探
         ├─ 无乱码 → 返回（codepage = 'acp'）
         └─ 乱码 → 换 -mcp=GBK 重解到 dest 内的临时子目录 __mv_retry_<uuid8>
                ├─ 重解失败（真机 7z 不认）或重解仍乱码 → 丢弃重解结果、保留原结果
                │    且 zip 可走 adm-zip + GBK decoder 兜底（≤ maxBytesForJsFallback）
                └─ 更干净 → 清掉原内容、把干净结果上移（原结果再乱也比空目录强）
```

**三个关键设计决策**：
1. **由乱码嗅探驱动重试，而不是修错误匹配正则** —— 正则只能匹配已知错误形态，
   嗅探对**任何**码页不匹配都生效（含英文系统 ACP=1252 的机器）。
2. **重解输出到 `dest` 内的临时子目录**（`__mv_retry_<uuid8>`），解完嗅探、**更干净才替换**——
   原结果再乱也比空目录强，所以重解失败时**绝不破坏**已解出的内容；且临时目录随 staging 一起清理，绝不泄漏。
3. **密码/损坏/超时不重试** —— 换码页救不了这三种，直接抛可行动错误，也避免把 GB 级包解两遍。

`ExtractResult.codepage` 联合类型扩为 `'acp' | 'gbk' | 'utf8'`（`acp` = 裸参数的系统代码页，
中文系统上即 936/GBK，但不是显式指定，如实标注）。`isUnknownSwitch` / `codepageAttempts` / `sevenZipExtract` 已删除（无消费者）。

### 12.2 删除链路失效（P0，T-R2）——根因与修法

**根因**：`main/index.ts` 的 `shell:trash` handler 直接调 `trash` npm 包（v10，纯 ESM）。打包后 `trash` 从 **app.asar 内部**加载，其 `lib/windows.js` 用 `new URL('windows-trash.exe', import.meta.url)` 拼出 **asar 内部路径**，再经 ESM 导入的 `execFile` spawn——可执行文件无法从 asar 归档内启动，实测报 `spawn …app.asar\node_modules\trash\lib\windows-trash.exe ENOENT`。`trash()` 静默 reject → handler 把每个路径塞进 `failed` → 渲染层 `removed` 为空直接 return → **资产原地不动且毫无提示**。同一根因也影响导入后的原包回收（`disposeArchive` → `await import('trash')`，archiveDisposal=recycle 时静默保留原包）。

**实测复现路径**（本轮用 CDP 驱动打包态应用完成，非推断）：复制 `release-v001/win-unpacked` → 给 asar 内 `out/main/index.js` 打一行 `app.commandLine.appendSwitch("remote-debugging-port","9222")` → 重打包 → CDP 连渲染进程 → 点卡片 / Delete / 确认删除 → 5 秒宽限到期后文件夹仍在；给 handler 加日志后抓到上述 ENOENT 堆栈。

**修法**：
- 新增 `src/main/trash.ts`（**零 electron 依赖，可单测**）：`trashOne` = 先 `shell.trashItem`（Electron 内置，无外部可执行文件，**asar 内可用**）→ 失败再 `trash` 包兜底 → 都失败抛首选错误；`trashPaths` 批量返回失败清单。
- `main/index.ts`：handler 改走策略（失败记 `console.error` + 返回清单，不再静默）；`runImport` 注入 `disposeArchiveWithStrategy`（三档：keep / delete=fs.rm / recycle=策略）。
- `src/renderer/store.ts` `commitDelete`：全失败 → 写 `notice`（「删除失败：N 个资产未能移入回收站…已保留在原位置」）；部分失败 → 分别计数提示。**失败不再静默**。
- **实测验证**：同一 CDP 探针把 handler 换成 `shell.trashItem` 后，含中文文件名的目录与单文件都真实进入 Windows 回收站（`$Recycle.Bin` 元数据可见原路径），完整 UI 流程（点卡片→Delete→确认→5s 到期）资产从网格/索引/磁盘三处消失。

**回归测试**：`tests/trashStrategy.test.ts`（策略顺序 / 兜底 / 失败上报，钉住「trashItem 可用时兜底烂掉也无感」）；`tests/deleteFlowFix.test.ts`（驱动真实 store action：requestDelete→confirm→commit 全链 + trashPaths 桩真删临时目录断言磁盘消失 + 撤销语义 + **失败不再静默**两条回归）。

### 12.4 SKP 内嵌预览图提取（T-R4，P1-2）

**真实样本实测结论**（本机两个 .skp，SU 版本头均为 `FF FE FF 0E` + UTF-16LE `{8.0.1}`，即 parseSkpVersion 报「SU 8」）：

SU 二进制布局：版本头 → VersionMap 骨架（`CThumbnail` section → … → `End-Of-Version-Map`）→ **`CDib` 属性段**（通用前缀 `FF FF 03 00 04 00` + ASCII 属性名 `CDib` + flags(4) + len(4) + 图片字节）。

| 样本 | CDib 偏移 | 内容 | 结论 |
| --- | --- | --- | --- |
| A 侘寂挂画（1.36MB） | 1973（图片@1991） | 256×256 PNG，54836 B | **真实模型预览**，视觉核实 |
| B 中古侘寂屏风（108MB） | 9383（图片@9401） | 512×512 JPEG，176025 B | SU 把木纹材质图写进了缩略图槽（该包无可用模型渲染） |

- 新模块 `src/main/skpPreview.ts`（纯 IO 零 electron，可单测）：**CDib 锚定优先**（精准命中缩略图槽位）→ 找不到 CDib 退回「头部第一个结构完整的图片」启发式 → 都没有返回 null。图片终止用**结构校验**而非裸签名：PNG 走 chunk 链（IHDR→…→IEND），JPEG 走 marker 段（APPn/DQT/SOF/SOS→熵数据→EOI），噪声签名（只有 SOI/魔数没有完整结构）会被跳过而不是把后面的真图吸过来。
- 接线（`src/main/importer.ts`）：封面优先级 **skp 内嵌预览 > pickCover 四级回退 > SU 图标占位（渲染层）> 用户粘贴（manual）**。内嵌图落成资产文件夹内真实文件 `<skp 主名>.preview.<ext>`（理由：① 封面统一走 `vault://asset/…`，必须在库内；② 与 rescan 的 walkFiles 视图一致，不会出现 cover 指向 files 外文件；③ CoverPicker 可从 files 里再选它），`coverSource='embedded'`，文件进 files/体积。
- 扫描窗口 512KB（实测预览在 2KB/9KB 偏移；108MB 大包也只读头部）。
- **测试**：`tests/skpPreview.test.ts` 19 条（PNG/JPEG 结构校验、噪声跳过、偏移优先、CDib 锚定 5 条、headBytes 窗口收窄、落盘/幂等/JPG 扩展名）；`tests/importerJunk.test.ts` 内含「样本 A + 内嵌预览」集成断言（cover=`znzmo-1180221079-1.preview.png`、coverSource=embedded、落盘字节与 fixture 一致）。

### 12.5 .rar 后缀但内容是 zip（T-R5）

### 13.4 ⚠️ vault:// 贴图进 WebGL 的 CORS 阻塞点（需主进程一行修复）

`src/main/protocol.ts` 的 `serveVault` 直接 `return net.fetch(pathToFileURL(abs).href)`，**响应不带 `Access-Control-Allow-Origin`**；`registerSchemesAsPrivileged` 的 privileges 里也没有 `corsEnabled`（`bypassCSP` 只绕过 CSP，不涉 CORS）。vault:// 对渲染进程是跨源协议，TextureLoader 走 `crossOrigin=anonymous`，**当前实现下所有贴图会加载失败**（组件不白屏，但球是灰的）。这是本组件唯一的运行时阻塞点，GUI 手工验证跑不了（无头环境无 GPU），故以代码审查结论如实标注。

**修复（main/preload owner 一行）**：`serveVault` 里给响应加头再返回：

```ts
const resp = await net.fetch(pathToFileURL(abs).href)
const headers = new Headers(resp.headers)
headers.set('Access-Control-Allow-Origin', '*')
return new Response(resp.body, { status: resp.status, headers })
```

备选绕开（不改主进程）：未来加 IPC 读文件转 data URL，经 `textureUrls` prop 覆盖（组件已留此口子）。

### 15.1 任务 5：vault:// 协议加 CORS 响应头（阻塞项）

**匹配强度决策（刻意保守，全部有测试钉住）**：
1. **中文词（含 CJK）**：命中 = 某 CJK token 的**后缀或全等**（token = 按 `非字母数字+CJK` 切分的连续段）。依据：中文产品名**中心语后置**（「北欧椅子」「实木门」尾部是品类词），而「藤编屏风」头部的「藤编」只是材料修饰语——若按任意位置 `includes`，整包屏风模型会被误拉进贴图频道 木材/藤编（样本 A 实证过这个误报）。不做单字模糊。
2. **纯 ASCII 词**（当前词表仅「LOFT」）：token 全等、大小写不敏感（子串会误伤：`art` ⊂ `Apart`）。**当前词表几乎全中文，英文资产名（AmbientCG/PolyHaven 等）一律落 null**——词表源自知末中文电商词表，不做音译/意译猜测，宁缺勿错。
3. 含 `/` 词条（「椅子/凳子」等）：拆子词任一命中即算，落盘仍是完整词条。
4. **二级 > 一级；同层最长词优先**（「卫生间瓷砖」不被「卫生间」截胡成 家装/卫生间）；等长按 `LEVEL2_MAP` 键序。
